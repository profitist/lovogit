# Ручной анализ обновления проекта

Команда анализирует одну прямую зависимость GitHub-проекта: получает снимок default branch,
определяет current по файлам, выбирает последний стабильный неотозванный PyPI-релиз,
читает опубликованные материалы и ищет потенциально затронутые места в Python-коде.

Настройте `.env` по `.env.example`: `GITHUB_TOKEN` с доступом к репозиторию обязателен.
`BOT_TOKEN` не нужен. LLM-настройки проверяются только при достижении анализа текстов.
Поддержан `LLM_PROVIDER=openai_compat`, включая Polza с `LLM_BASE_URL=https://polza.ai/api/v1`.
Извлечение использует `MODEL_CHEAP`, поиск с инструментами — `MODEL_STRONG`.
Канал и модель поиска должны поддерживать tool calling. Google GenAI пока не поддержан этой командой.
Пустой `LLM_REASONING_EFFORT` не передаётся провайдеру; для текущих Polza IDs режим задан в имени модели.

## Лимиты

Настройки можно задавать в окружении или `.env`:

| Настройка | По умолчанию |
| --- | --- |
| `UPDATE_DEADLINE` | 600 секунд на запуск |
| `UPDATE_MAX_CHANGES` | 10 исследуемых изменений |
| `UPDATE_MODEL_CALLS` | 12 генераций на изменение |
| `UPDATE_TOOL_CALLS` | 24 поисковых вызова на изменение |
| `UPDATE_COMPARE_TIMEOUT` | 60 секунд на исследование изменения |
| `UPDATE_MAX_TOKENS` | 5000 выходных токенов на генерацию |
| `UPDATE_TRACE_BYTES` | 20971520 байт model/tool данных |
| `UPDATE_TOOL_CHARS` | 30000 символов на запись инструмента |
| `UPDATE_SNIPPET_LINES` | 20 строк фрагмента |
| `UPDATE_SNIPPET_CHARS` | 8000 символов фрагмента |

Также действуют независимые лимиты GitHub, selection, fetch и extraction.
После deadline новые этапы не начинаются; очистка ресурсов и завершение уже запущенной
синхронной индексации могут занять дополнительное время. Лимиты и усечения видны в отчёте.

## Langfuse

Локальный трейс сохраняется всегда. Отправка требует явного `--langfuse` и настроенных
`LANGFUSE_HOST`, `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`. Трейс содержит прочитанные
фрагменты проекта, сообщения модели и инструменты. Ключи и authorization headers в него не входят.
Ошибка экспорта хранится отдельно от результата анализа и даёт ненулевой exit code.

Повторная отправка сохранённого трейса без повторения анализа:

```sh
PYTHONPATH=src .venv/bin/python -m lovogit.cli.export_trace artifacts/runs/<run-id>
```

Receipt `langfuse-export.json` запрещает повтор для accepted/partial и неизвестного исхода,
поскольку сервер мог уже принять данные. Явный отказ до принятия допускает повтор.
Стоимость сохраняется только при наличии данных провайдера и с исходной валютой;
значения в RUB не объявляются стоимостью в USD.

## Запуск из корня checkout

```sh
uv sync
PYTHONPATH=src .venv/bin/python -m lovogit.cli.analyze_update \
  --repo https://github.com/team/project \
  --package httpx
```

Замените URL и имя пакета своим проектом и прямой зависимостью. Добавьте `--langfuse`,
если хотите отправить трейс. `--source requirements` явно выбирает requirements.txt,
`--source pyproject` — PEP 621 pyproject.toml; по умолчанию источник выбирает инвентарь.

Current берётся только из однозначного pin или поддержанного согласованного lock.
Диапазон без lock не разрешается. Несколько деклараций одного пакета приводят к skipped
с перечислением кандидатов — платформа и optional-группа не угадываются.
Latest stable выбирается без фильтра ограничений проекта и не означает допустимость установки.

CLI напечатает путь `artifacts/runs/<run-id>/report.html`. Каталог каждого запуска уникален:

```text
report.html          самостоятельный читаемый отчёт
report.json          структурированные результаты этапов
trace.json           сообщения модели, инструменты, время и usage
langfuse-otel.json   сохранённый payload для экспорта
langfuse-export.json receipt, только если отправка запрашивалась
code-index.sqlite   собственный индекс запуска, если выполнялся поиск
```

HTML показывает принятые изменения, исходные материалы с выделенными цитатами,
сырой ответ модели, отклонённые записи и потенциально затронутый код с привязкой к SHA.
Проверенные фрагменты кода доступны после удаления временного снимка.
Все артефакты игнорируются Git. Ключи остаются в `.env`, не в отчёте.

| Статус | Exit code | Значение |
| --- | --- | --- |
| completed | 0 | Предусмотренные операции завершены |
| no_update | 0 | Более нового подходящего стабильного релиза нет |
| skipped | 0 | Нет однозначного поддержанного входа, причина в отчёте |
| partial | 2 | Есть пропуски, ошибки части анализа или исчерпаны бюджеты |
| failed | 1 | Обязательный этап завершился ошибкой |
| прерывание | 130 | Запуск отменён, доступные результаты сохранены насколько возможно |

Неудачный запрошенный экспорт даёт code 1 независимо от статуса анализа.
Ошибка сохранения сообщает о невозможности записать отчёт; наличие каталога не означает успешный прогон.

Поиск охватывает Python-код и может пропустить динамические импорты и непрямые использования.
Найденное место — кандидат для проверки, а не доказанная регрессия. Пустой поиск и совпавшая
цитата не доказывают совместимость. Полнота истории релизов неизвестна даже при completed.
Тесты не выполняются, зависимости не устанавливаются, проект и БД мониторинга не меняются.

Offline-проверка связки на fixture без ключей и платных вызовов:

```sh
PYTHONPATH=src:tests .venv/bin/python -m unittest discover \
  -s tests -p 'test_project_update_*.py'
```
