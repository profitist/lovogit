# LovoGit — фронтенд (MVP)

Telegram Mini App для подробного просмотра результатов мониторинга: реестр зависимостей проекта и критичность перехода на новые версии. Основной интерфейс — уведомления Telegram-бота; Mini App открывается из меню бота или кнопкой «Подробнее» в уведомлении. Продукт и состав MVP — в [mvp.md](mvp.md), развёртывание, формат отчёта и принципы — в [dev-docs.md](dev-docs.md).

## 1. Границы

Фронтенд **только показывает** то, что уже посчитал бэкенд. Он не меняет зависимости и код проекта и не запускает анализ.

В MVP два экрана:

1. **Реестр** — все зависимости проекта и сводка по критичности.
2. **Зависимость** — отчёт по одной зависимости.

Mini App не меняет настройки, проекты и уведомления. Проекты добавляются через `/add_repo <github-url>` в Telegram-боте в общий список экземпляра; токены бота и GitHub и разрешённые чаты задаются при развёртывании.

Доступ: Mini App передаёт бэкенду `initData` Telegram, бэкенд проверяет подпись и пускает только разрешённых пользователей. Своего экрана входа нет; при отказе в доступе показывается сообщение об этом, а не пустой реестр.

## 2. Статусы зависимости

Один статус на зависимость. Три уровня риска взяты из описания продукта: «низкорисковое», «требуется дополнительная проверка», «вероятна несовместимость». Остальные три — состояния, без которых экран врёт: новой версии нет, анализ ещё идёт, анализ не удался.

Порядок — от самого срочного; в нём же сортируется реестр.

| # | Статус | Когда |
|---|---|---|
| 1 | Вероятна несовместимость | в новой версии изменено или удалено API, которое найдено в коде проекта |
| 2 | Требует проверки | есть изменения, влияние которых на проект не удалось подтвердить или исключить |
| 3 | Анализ не удался | новая версия найдена, но проанализировать её не получилось; причина показывается |
| 4 | Ждёт анализа | новая версия найдена, анализ ещё не завершён |
| 5 | Низкий риск | анализ не нашёл изменений, затрагивающих проект |
| 6 | Актуальна | новее текущей версии нет |

Статус всегда показывается **текстом и цветом вместе**, не только цветом.

«Низкий риск» не означает «совместимо» — рядом всегда есть ссылка на границы анализа (раздел 4). В интерфейсе нигде нет слов «безопасно» или «совместимо» и зелёной галочки «можно обновлять».

## 3. Экран «Реестр»

Главный экран отвечает на один вопрос: **что требует внимания прямо сейчас?**

```
┌──────────────────────────────────────────────────────────────────┐
│ my-project                          Последняя проверка: 12:40    │
├──────────────────────────────────────────────────────────────────┤
│ [ 2 Несовместимость ] [ 5 Проверить ] [ 1 Не удался ]            │
│ [ 0 Ждёт ] [ 7 Низкий риск ] [ 41 Актуальна ]                    │
├──────────────────────────────────────────────────────────────────┤
│ Поиск: [__________]                                              │
│                                                                  │
│ Зависимость      Текущая  Новая   Статус             Мест  Ссылки│
│ example-sdk      1.8.2    2.0.0   ● Несовместимость    3   ⧉ ⧉ ⧉ │
│ another-lib      3.1.0    3.2.0   ● Проверить          1   ⧉ ⧉ ⧉ │
│ ...                                                              │
└──────────────────────────────────────────────────────────────────┘
```

**Шапка**: название проекта и время последней проверки. Если мониторинг сейчас не работает или последняя проверка завершилась ошибкой — заметная строка под шапкой с причиной. Иначе пользователь примет старые данные за свежие.

**Сводка критичности** — по счётчику на каждый статус. Это и есть дашборд: видно общую картину, клик по счётчику фильтрует таблицу по этому статусу, повторный клик снимает фильтр. Счётчики с нулём видны, но приглушены.

**Таблица**:

| Колонка | Что | Примечание |
|---|---|---|
| Зависимость | имя пакета | клик по строке открывает экран зависимости |
| Текущая | версия в проекте | |
| Новая | последняя доступная | пусто, если статус «Актуальна» |
| Статус | из раздела 2 | |
| Мест | сколько участков кода затронуто | пусто, пока анализа нет |
| Ссылки | репозиторий, страница пакета, changelog | только те, что известны; открываются во внешнем браузере (`openLink`) |

- Сортировка по умолчанию — по статусу (раздел 2), внутри статуса — по имени. Клик по заголовку колонки меняет сортировку.
- Поиск — по имени зависимости, фильтрует на лету.
- Неизвестная ссылка не показывается совсем, а не ведёт на пустую страницу. У иконок ссылок есть подписи-подсказки: «Репозиторий», «PyPI», «Changelog».

## 4. Экран «Зависимость»

Отвечает на вопрос: **что сделать перед обновлением и почему?** Блоки идут сверху вниз в порядке важности.

1. **Заголовок**: имя, `1.8.2 → 2.0.0`, статус, ссылки (репозиторий, страница пакета, changelog, release notes).
2. **Вывод**: причина оценки и рекомендация — одним-двумя предложениями, как в отчёте из [dev-docs.md](dev-docs.md).
3. **Затронутый код**: список `путь/к/файлу.py:строка` и какой элемент API там используется. Кнопка копирования пути. Если строку определить не удалось — показывается только файл.
4. **Что изменилось**: изменения из changelog и release notes, которые анализ счёл значимыми. У каждого — ссылка на источник и отметка: «используется в проекте» или «в коде не найдено».
5. **Границы анализа**: что проверено и что не проверено (например, какие источники были недоступны). Блок есть всегда, в том числе при статусе «Низкий риск».
6. **История проверок**: дата, версии, статус. Свёрнута по умолчанию.

Для статуса «Анализ не удался» вместо блоков 2–4 показывается причина. Для «Ждёт анализа» — что новая версия найдена и анализ ещё не завершён.

**Факт отдельно от предположения.** Утверждение, подтверждённое источником или найденным кодом, показывается со ссылкой на него. Утверждение без такого подтверждения помечается словом «предположение». Это прямое требование принципа доказательности.

У экрана свой адрес — deep link Mini App с параметром `startapp` (например, `t.me/<bot>/<app>?startapp=example-sdk`). Им открывается кнопка «Подробнее» из уведомления, и его же можно переслать. «Назад» к реестру — через `BackButton` Telegram.

## 5. Общие правила интерфейса

- **Пустые состояния говорят, что делать или чего ждать**: «Проект ещё не проверялся — первая проверка запустится автоматически», а не пустая таблица.
- **Ошибка загрузки данных** — сообщение на месте контента и кнопка «Повторить».
- **Сначала телефон**: Mini App открывают в основном из мобильного Telegram. На узком экране таблица реестра превращается в список карточек (имя, версии, статус), экран зависимости — в одну колонку.
- **Тема Telegram**: цвета берутся из `themeParams`, светлая и тёмная тема подхватываются автоматически. Цвета статусов остаются своими и сохраняют контраст в обеих темах.
- **Время** — относительное («5 мин назад»), точное — во всплывающей подсказке.
- **Доступность**: всё работает с клавиатуры, у иконок есть текстовые подписи, контраст текста не ниже WCAG AA.

## 6. Какие данные нужны экранам

Только то, что MVP и так производит; новых сущностей фронтенд не требует.

**Реестр**: название проекта; время, результат и ошибка последней проверки; по каждой зависимости — имя, текущая и последняя версии, статус, число затронутых мест, ссылки (репозиторий, страница пакета, changelog).

**Зависимость**: всё из реестра плюс ссылка на release notes, причина, рекомендация, затронутые места (файл, строка, элемент API), значимые изменения (текст, ссылка на источник, найдено ли в коде, подтверждено или предположение), границы анализа (проверено / не проверено), причина неудачи анализа, история проверок (дата, версии, статус).

Формат API согласуется вместе с бэкендом. Черновик — демо-данные в `src/view/mockups/data/`: прод-страницы (`src/view/app/`) ждут от `/api/registry` и `/api/dependencies/{name}` ответы ровно такой формы. У затронутого места есть необязательное поле `kind` (`removed` / `deprecated`), которого нет в списке выше.

## 7. Не решено

- Как выбирать проект в Mini App: экземпляр содержит несколько проектов одной команды. Все разрешённые чаты видят общий набор; `/status` уже показывает общую сводку в боте. Выбор проекта и изменение адресов API Mini App будут отдельной задачей и пока не реализованы.
- Откуда берутся ссылки на репозиторий и changelog — зависит от выбора источников в [dev-docs.md](dev-docs.md), раздел «Не решено».
- Окончательная шкала риска: три уровня из раздела 2 взяты из описания продукта и требуют подтверждения.
- Стек фронтенда.


## 8. Связь со сводкой бота

`/status` получает данные через сервисный слой и показывает все проекты экземпляра, без кнопок перехода в текущие экраны. Для каждой сводки отличать последний запуск от последнего успешного снимка: при ошибке старые оценки не становятся свежими. Отсутствие успешного снимка — отсутствие оценок, а не шесть нулевых счётчиков. Шкала шести статусов согласована с разделом 2. Хранение истории и команда бота не добавляют в Mini App API, переключатель проектов, проверку initData или рассылку дайджестов; эти части ещё предстоит реализовать.
