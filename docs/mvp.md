## 1. Описание проекта

SessionFlow — локальное приложение, которое автоматически обнаруживает сессии Claude Code, отслеживает их состояние и отображает в едином интерфейсе в виде Kanban-доски.

Цель проекта — сделать работу с несколькими AI coding-сессиями более прозрачной и управляемой.

При параллельной работе с несколькими задачами разработчик может терять контекст, забывать о незавершённых сессиях, не замечать запросы на подтверждение и тратить время на восстановление того, что делал каждый агент.

SessionFlow должен решать эту проблему, предоставляя единую точку управления сессиями.

В дальнейшем проект может превратиться в интеллектуальный оркестратор, который анализирует задачи, обнаруживает конфликты и помогает координировать работу нескольких AI-агентов.

## 2. Цели проекта

- Автоматически обнаруживать локальные сессии Claude Code.
- Отображать сессии на единой Kanban-доске.
- Определять и показывать актуальное состояние каждой сессии.
- Показывать, над какой задачей работает каждая сессия.
- Сохранять контекст, краткие сводки и историю изменений состояния.
- Помогать быстро находить зависшие, завершённые и ожидающие вмешательства сессии.
- Предоставлять удобный интерфейс для управления задачами и сессиями.

**Ключевой принцип:** пользователь должен понимать состояние всех своих AI coding-задач, не открывая каждую сессию отдельно.

## 3. Целевая аудитория

На первом этапе — сам разработчик, работающий с Claude Code и несколькими проектами одновременно.

В дальнейшем продукт может быть полезен разработчикам, которые параллельно используют несколько AI coding-агентов или работают над несколькими репозиториями.

## 4. Состав MVP

Первая версия должна решать одну задачу: показывать все обнаруженные сессии Claude Code на понятной локальной Kanban-доске.

В MVP входят:

1. Обнаружение локальных сессий.
2. Чтение и разбор истории сессий.
3. Определение доступного состояния сессии.
4. Локальная база данных.
5. Kanban-интерфейс.
6. Просмотр деталей сессии.
7. Название и краткая сводка с помощью ИИ.
8. Фильтрация по проектам.
9. Сохранение состояния между перезапусками.
10. Обработка ошибок мониторинга.

Не входят в первую версию (см. [backlog.md](backlog.md)):

- Автоматическое изменение кода.
- Автоматическое выполнение терминальных команд.
- Полноценная поддержка других coding-агентов.
- Автоматическое распределение задач между сессиями.
- Сложная многоагентная система.
- Облачная синхронизация и командная работа.

## 5. Критерии готовности MVP

MVP считается готовым, если:

- Новые сессии Claude Code автоматически появляются на доске.
- Существующие сессии обнаруживаются после запуска приложения.
- Карточки содержат корректные идентификаторы и привязку к проектам.
- Статус обновляется при поступлении новых событий.
- Пользователь может открыть подробности сессии.
- Краткие сводки формируются и сохраняются.
- Перезапуск приложения не приводит к потере пользовательских данных.
- Ошибки чтения истории не приводят к остановке всего мониторинга.
- Интерфейс позволяет понять состояние сессий без ручного чтения каждого диалога.

## 6. Главный принцип разработки

Сначала сделать надёжный мониторинг и полезную Kanban-доску.
Затем добавить понимание контекста сессий.
И только после этого — автономное управление и оркестрацию.

Проект должен быть полезен уже на первом этапе, даже если ИИ временно недоступен.
