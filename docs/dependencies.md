# Зависимости проекта

Статический инвентарь читает файлы одного корневого проекта в готовом снимке
исходников. Он возвращает результат в памяти: таблица `dependencies` остаётся
хранилищем прежних данных и не используется как парсер.

## Выбор источника

`source="auto"` выбирает корневой `pyproject.toml` с таблицей `project`, иначе
`requirements.txt`. Пустой список в PEP 621 остаётся пустым — он не дополняется
requirements. Корректный tool-only pyproject позволяет выбрать requirements;
неверный TOML даёт ошибку без скрытого переключения источника.

`source="pyproject"` и `source="requirements"` выбирают источник явно.
Файлы не объединяются автоматически. Вложенные проекты и самостоятельные
requirements-dev.txt не сканируются; файлы requirements доступны через локальные
включения выбранного корневого requirements. `uv.lock` относится только к
выбранному pyproject. Список обнаруженных файлов содержит и невыбранные.

## Результат

Инвентарь сохраняет repo identity и commit SHA, декларации, constraints,
происхождение, диагностику и SHA-256 прочитанных файлов. Пути относительны корню:
для requirements указаны строки, для TOML — ключ и индекс. DTO не обращается
к временному каталогу после завершения разбора.

| Статус | Значение |
| --- | --- |
| `complete` | Поддержанный выбранный источник разобран полностью; версии могут быть неизвестны |
| `partial` | Есть пропуски, неподдержанные записи, проблемы включений или выбранного lock |
| `failed` | Выбранный корневой источник нельзя прочитать или разобрать |
| `no_sources` | Поддержанного корневого источника нет; это не доказанный пустой список |

Версия декларации имеет отдельное состояние `declared_pin`, `locked`,
`unresolved`, `conflict` или `unsupported`. `current_version` nullable.
Ни pin, ни lock не доказывают установку в рабочем окружении, импорт пакета
или совместимость обновления. Парсер не обращается к сети, LLM, установленным
пакетам контроллера, pip/uv, build backend и БД.

## Лимиты чтения

`InventoryLimits` по умолчанию: 128 файлов, 16 уровней включений, 8 MiB на файл,
32 MiB суммарно и 100 000 логических записей. Все бюджеты — положительные целые.
Повторное чтение использует кэш байтов, обработка включений тоже ограничена.
Symlink, специальные файлы и выход за корень запрещены. Относительный `..`
допустим, если остаётся внутри корня. Цикл или лимит не возвращает complete.

## Поддержанный синтаксис

| Источник | Поддержка |
| --- | --- |
| `project.dependencies` | PEP 508 строки; обязательная область runtime |
| `project.optional-dependencies` | Каждая группа отдельно, без автоматического включения в runtime |
| `project.dynamic` | Не вычисляется; объявленные динамические зависимости дают partial |
| `dependency-groups` | Вне охвата, диагностируются; build-system.requires не входит в runtime |
| requirements | UTF-8/BOM, пустые строки, комментарии, продолжения backslash, именованные PEP 508 требования |
| Локальные включения | `-r file`, `-rfile`, `--requirement file`, `--requirement=file`; аналогичные формы `-c`/`--constraint` |
| Hashes | Повторяющиеся `--hash=algorithm:value` или `--hash algorithm:value` сохраняются без скачивания и проверки |
| Direct URL/VCS/editable | Именованные записи сохраняются как unsupported; версия неизвестна |
| Прочие pip options, remote includes, `${VAR}` | Диагностика partial; не исполняются и не подставляются |
| Poetry, Pipenv, setup.py/setup.cfg | Не разбираются и не выполняются |

Например, requirements может содержать:

```text
-r sub/base.txt
-c constraints.txt
```

В `sub/base.txt`:

```text
httpx>=0.27,<1
```

В `constraints.txt`:

```text
httpx==0.28.0
urllib3==2.2.3
```

Инвентарь содержит httpx с `declared_pin`, `current_version="0.28.0"` и
происхождением из обоих файлов. Один constraint не объявляет зависимость:
urllib3 не появляется в списке dependencies.

Без constraint и lock `httpx>=0.27,<1`, `httpx==0.28.*` и просто `httpx` дают
`complete` + `unresolved` + null version. Точный `==0.28.0` даёт declared_pin,
пока нет противоречий. `===` допускается для PEP 440 версии; произвольная версия
остаётся unsupported. Совместно применимые противоречащие pins дают conflict.

Markers сохраняются, а не оцениваются по ОС/Python контроллера. Разные
условные варианты и optional-области не сводятся к одной глобальной версии.
Условный constraint не устанавливает безусловно применимую текущую версию.
Причины неизвестности и неподдержанного синтаксиса доступны в diagnostics и
полях version_state/reason. Повторные одинаковые декларации сохраняют все
места происхождения.

## Версии из uv.lock

Начальный поддержанный формат: TOML `version=1`, `revision=3`, один корневой
проект с `source.virtual="."` или `source.editable="."`. Другие revisions,
workspace и настройки tool.uv, меняющие resolution/sources, диагностируются;
uv не запускается для экспорта, проверки или обновления lock.

Перед подтверждением сравниваются имя корневого проекта, requires-python
и metadata.requires-dist с текущими статическими декларациями, включая extras,
markers и optional-области. Порядок строк и написание нормализованных имён не
существенны. Если свежесть нельзя подтвердить в поддержанном подмножестве,
версия остаётся неизвестной. Это не полная замена `uv lock --check`.

Для `httpx>=0.27,<1` согласованный lock с единственным прямым registry-кандидатом
0.28.0 даёт `locked`, `current_version="0.28.0"` и происхождение из обоих файлов.
Транзитивные записи и сам проект не добавляются к прямым зависимостям.

| Ситуация | Результат |
| --- | --- |
| Metadata не соответствует текущему манифесту | `lock_metadata_mismatch`, версия не подтверждена |
| Нет корневого ребра или записи | `missing_lock_entry` |
| Несколько версий без однозначной применимости | `ambiguous_lock`, кандидаты сохранены |
| Resolution markers или условные рёбра вне поддержанной семантики | `conditional_lock`, без выбора платформы |
| Несколько registry sources без однозначной связи | `ambiguous_lock_source` |
| Версия противоречит декларации | `conflict` / `lock_version_conflict` |
| Неизвестная revision или повреждённый TOML | Диагностика, без fallback к объявленному pin |

Например, смена `>=0.27,<1` на `>=0.26,<1` делает прежнюю metadata несогласованной,
хотя версия 0.28.0 всё ещё подходит диапазону. Попадания версии в диапазон
недостаточно для подтверждения lock. Несколько кандидатов не означают выбор
наибольшего. Сведения из повреждённого или неподдержанного lock не выдаются за
установленное окружение; исходный pin остаётся в декларации, current_version — null.

## Вызов на готовом снимке

```python
import asyncio

from lovogit.app.dependencies.inventory import read_dependency_inventory


async def inspect_project(repo_service, github_url):
    async with repo_service.open_source(github_url) as snapshot:
        result = await asyncio.to_thread(read_dependency_inventory, snapshot)
    return result
```

Передайте `RepoService` с готовым GitHubProvider. Вызов должен завершиться до
выхода из контекста снимка. Возвращённый DTO остаётся доступен после cleanup.
Для явного источника передайте `source="requirements"` в to_thread.
Сам парсер синхронный, ограниченный бюджетами; он не создаёт event loop,
сетевые клиенты и сессии БД. Расширенный инвентарь ещё не сохраняется и не
запускает выбор целевой версии, анализ changelog или мониторинг автоматически.

Автономные проверки:

```sh
PYTHONPATH=src:tests .venv/bin/python -m unittest test_dependency_inventory test_dependency_files test_dependency_parsing test_dependency_versions test_dependency_lock test_dependency_snapshot
```
