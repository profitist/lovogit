# project-monitoring-state Specification

## Purpose

Хранить проверяемую историю мониторинга каждого проекта и предоставлять согласованное состояние для сводок бота и будущих дайджестов.

## Requirements

### Requirement: История запусков проекта
Система MUST сохранять для каждого запуска идентификатор проекта, время начала, состояние `running`, `succeeded` или `failed`, время завершения и причину ошибки при неудаче. Завершённый запуск MUST быть неизменяемым.

#### Scenario: Успешное завершение
- **WHEN** выполняющийся запуск завершается успешно
- **THEN** сохраняются состояние `succeeded` и время завершения, а запись остаётся в истории после перезапуска приложения

#### Scenario: Ошибка мониторинга
- **WHEN** выполняющийся запуск завершается ошибкой
- **THEN** сохраняются состояние `failed`, время завершения и непустая причина ошибки

#### Scenario: Повторное завершение
- **WHEN** поступает попытка изменить результат уже завершённого запуска
- **THEN** система отклоняет её без изменения истории

### Requirement: Снимок результатов зависимостей
Система MUST хранить в успешном запуске по одному результату каждой проверенной зависимости: имя, текущую и последнюю известную версии и один статус `incompat`, `review`, `failed`, `waiting`, `low`, `current`. Неизвестный статус и дубликаты имён в одном снимке MUST отклоняться.

#### Scenario: Шесть состояний
- **WHEN** сохраняется снимок с зависимостями во всех шести статусах
- **THEN** статусы и версии доступны после повторного чтения, включая отсутствие последней версии у `current`

#### Scenario: Неверный снимок
- **WHEN** снимок содержит неизвестный статус либо повторяющееся имя зависимости
- **THEN** сохранение всего снимка отклоняется

### Requirement: Атомарность завершения проверки
Система MUST публиковать успешный снимок и завершение его запуска атомарно. Ошибка сохранения MUST оставлять ранее опубликованное состояние неизменным. Ошибка мониторинга MUST NOT заменять последний успешный снимок частичными данными.

#### Scenario: Сбой записи
- **WHEN** сохранение одного результата в новом снимке завершается ошибкой
- **THEN** ни новый успешный снимок, ни успешное завершение запуска не становятся видимыми

#### Scenario: Неудача после успеха
- **WHEN** после успешной проверки следующая проверка завершается ошибкой
- **THEN** доступны ошибка новой проверки и отдельно последний успешный снимок с его временем

### Requirement: Однозначное состояние проекта
Система MUST отдельно предоставлять последний запуск и последний успешный снимок проекта. Последний запуск определяется временем начала с идентификатором для разрешения равенства; успешный снимок — порядком начала успешных запусков. Незавершённые данные MUST NOT включаться в счётчики.

#### Scenario: Проверка выполняется
- **WHEN** новый запуск выполняется, а успешный снимок уже существует
- **THEN** состояние содержит выполняющийся запуск и счётчики предыдущего успешного снимка с отдельным временем

#### Scenario: Запуски завершились в обратном порядке
- **WHEN** более старый запуск завершается после более нового успешного запуска
- **THEN** текущим остаётся снимок более нового запуска

### Requirement: Отсутствие анализа отличается от пустого результата
Система MUST различать отсутствие успешного снимка и успешную проверку без зависимостей. При отсутствии снимка счётчики MUST быть недоступны, а не равны нулю.

#### Scenario: Проект ещё не проверялся
- **WHEN** у проекта отсутствуют запуски
- **THEN** возвращается отсутствие последней проверки и отсутствие счётчиков

#### Scenario: Пустой успешный снимок
- **WHEN** успешная проверка сохранила пустой список зависимостей
- **THEN** все шесть счётчиков равны нулю и доступно время снимка
