# bot-project-status Specification

## Purpose

Предоставлять участникам разрешённых чатов достоверную общую сводку мониторинга всех проектов экземпляра через команду Telegram-бота.

## Requirements

### Requirement: Доступ по чату
Команда `/status` MUST проверять идентификатор чата по конфигурации до чтения проектов. Все участники разрешённого чата MUST иметь одинаковый доступ ко всему набору проектов экземпляра. Пустой список разрешённых чатов MUST запрещать доступ.

#### Scenario: Разрешённый чат
- **WHEN** любой участник разрешённого чата отправляет `/status`
- **THEN** команда читает общий набор проектов без фильтрации по пользователю или чату

#### Scenario: Доступ запрещён
- **WHEN** `/status` приходит из неразрешённого чата либо список разрешённых чатов пуст
- **THEN** бот отвечает «Нет доступа» без обращения к данным проектов

### Requirement: Общая сводка проектов
Команда `/status` MUST показывать все неудалённые проекты в стабильном порядке по имени и идентификатору. Для каждого проекта MUST быть указаны имя, идентификатор и число неудалённых зависимостей. Команда MUST только читать состояние без запуска проверки.

#### Scenario: Несколько проектов
- **WHEN** существуют несколько активных проектов и удалённый проект
- **THEN** ответ содержит каждый активный проект ровно один раз и не содержит удалённый проект

#### Scenario: Проекты отсутствуют
- **WHEN** активных проектов нет
- **THEN** бот сообщает «Проекты не настроены» и предлагает `/add_repo <github-url>` для подключения репозитория

### Requirement: Результат проверки и шесть счётчиков
Для каждого проекта команда MUST показывать время и состояние последнего запуска и причину его ошибки при неудаче. При наличии успешного снимка MUST показываться все шесть счётчиков с русскими названиями и время этого снимка; `low` MUST NOT обозначаться гарантией совместимости.

#### Scenario: Успешная проверка
- **WHEN** последний запуск проекта завершён успешно
- **THEN** ответ содержит время завершения и все шесть счётчиков, включая нули

#### Scenario: Проверка после успешного снимка завершилась ошибкой
- **WHEN** последний запуск неудачен, но есть предыдущий успешный снимок
- **THEN** ответ показывает причину ошибки, счётчики и время предыдущего снимка с явным предупреждением, что данные могут быть устаревшими

#### Scenario: Новая проверка выполняется
- **WHEN** последний запуск находится в состоянии `running`
- **THEN** ответ сообщает «Проверка выполняется» со временем начала; предыдущие счётчики, если есть, явно отнесены к предыдущему снимку

### Requirement: Недоступные оценки
При отсутствии успешного снимка команда MUST явно сообщать, что оценки обновлений пока нет, без нулевых счётчиков и утверждений об отсутствии проблем.

#### Scenario: Проверок ещё не было
- **WHEN** проект не имеет запусков
- **THEN** ответ содержит «Проверки ещё не выполнялись» и «Оценки обновлений пока нет»

#### Scenario: Первая проверка неудачна
- **WHEN** у проекта есть только неудачная проверка
- **THEN** ответ содержит её время и причину ошибки и сообщает об отсутствии оценок

### Requirement: Сервисный контракт чтения
Система MUST предоставлять сводку без Telegram-разметки и транспортных объектов. Ошибка мониторинга одного проекта MUST быть данными этого проекта и MUST NOT скрывать состояние остальных проектов.

#### Scenario: Смешанные результаты
- **WHEN** один проект имеет успешную проверку, а другой — неудачную
- **THEN** сервис возвращает оба проекта с их собственными состояниями

### Requirement: Ошибка чтения
При технической ошибке чтения команда MUST отправлять нейтральное сообщение о невозможности получить статус без имён проектов, SQL, трассировки или секретов. Подробности MUST записываться в журнал приложения.

#### Scenario: База данных недоступна
- **WHEN** получение сводки завершается технической ошибкой
- **THEN** бот сообщает «Не удалось получить статус. Попробуйте позже», а ошибка сохраняется в журнале

### Requirement: Полная доставка длинной сводки
Команда MUST доставлять все блоки проектов в сообщениях, не превышающих лимит Telegram 4096 символов, сохраняя порядок и не обрезая проекты или содержимое. Пользовательский текст MUST передаваться без интерпретации разметки.

#### Scenario: Большой набор проектов
- **WHEN** сводка превышает лимит одного сообщения
- **THEN** она отправляется последовательностью сообщений допустимой длины со всеми данными

#### Scenario: Специальные символы
- **WHEN** имя проекта или причина ошибки содержит символы HTML или Markdown
- **THEN** они отображаются как обычный текст
