# github-source-snapshot Specification

## Purpose

Предоставлять будущему анализу зависимостей воспроизводимый локальный снимок основной ветки GitHub-проекта, независимо от публичности репозитория и без загрузки истории Git.

## Requirements

### Requirement: Адрес репозитория
Система MUST принимать HTTPS URL корня репозитория github.com с необязательным `.git` и завершающим `/`, нормализовать его и отклонять другие хосты, схемы, credentials, query, fragment и пути внутри репозитория до сетевого обращения.

#### Scenario: Допустимые варианты адреса
- **WHEN** передан `https://github.com/team/project.git/`
- **THEN** используется репозиторий `team/project` с нормализованным URL `https://github.com/team/project`

#### Scenario: Недопустимый адрес
- **WHEN** передан SSH URL, URL другого хоста или адрес файла внутри репозитория
- **THEN** возвращается ошибка входных данных без сетевого запроса

### Requirement: Единый доступ через токен
Система MUST использовать настроенный токен экземпляра при обращениях к GitHub API без отдельного режима public/private. Провайдер MUST работать без настроек Telegram и LLM. Пустой токен MUST отклоняться до запроса; токен MUST NOT попадать в DTO, сообщения ошибок и журналы.

#### Scenario: Доступ к репозиторию
- **WHEN** настроенный токен имеет доступ к запрошенному репозиторию
- **THEN** получение снимка выполняется одинаково для публичного и приватного репозитория

#### Scenario: Настроек других компонентов нет
- **WHEN** заданы настройки GitHub, но отсутствуют Telegram- и LLM-настройки
- **THEN** провайдер может быть создан и использован

### Requirement: Фиксация основной ветки
Система MUST определять default branch из метаданных GitHub, разрешать её в конкретный commit SHA и получать исходники только этой ревизии. Результат MUST содержать GitHub ID репозитория, полное имя, нормализованный URL, имя ветки, SHA и корень локального снимка.

#### Scenario: Основная ветка называется иначе
- **WHEN** default branch репозитория называется `develop`
- **THEN** снимок соответствует SHA ветки `develop`, а не жёстко заданной `master` или `main`

#### Scenario: Ветка изменилась во время получения
- **WHEN** после разрешения ветки из SHA A в ней появился commit B
- **THEN** текущая операция получает снимок A и сообщает SHA A

#### Scenario: Нет доступной ревизии
- **WHEN** default branch не содержит доступного коммита или исчезла во время разрешения
- **THEN** операция возвращает ошибку отсутствия ревизии без локального снимка

### Requirement: Управляемый локальный снимок
Система MUST предоставлять снимок только после полного скачивания и распаковки. Каждая операция MUST владеть отдельным временным каталогом и освобождать его при выходе из контекста, ошибке и отмене. Снимок MUST NOT содержать историю Git; получение MUST NOT исполнять код проекта или устанавливать зависимости.

#### Scenario: Нормальное использование
- **WHEN** вызывающий код входит в контекст снимка и затем выходит из него
- **THEN** файлы доступны внутри контекста и принадлежащий операции каталог удалён после выхода

#### Scenario: Одновременное получение одного SHA
- **WHEN** две операции получают одинаковую ревизию
- **THEN** их каталоги независимы и завершение одной не удаляет снимок другой

#### Scenario: Прерванное получение
- **WHEN** скачивание или распаковка завершается ошибкой либо отменяется
- **THEN** снимок не возвращается, а временные данные операции удаляются

### Requirement: Ограниченная обработка архива
Система MUST ограничивать время сети, размер скачивания, объём распакованных данных и число файлов. Распаковка MUST отклонять выход за корень снимка, ссылки, специальные файлы и конфликтующие пути. Недопустимые redirects MUST отклоняться; токен MUST NOT передаваться на другой origin.

#### Scenario: Недопустимое содержимое
- **WHEN** архив содержит `../`, абсолютный путь, ссылку, конфликт путей либо превышает настроенный лимит
- **THEN** операция завершается ошибкой, не записывает файлы вне своего каталога и не публикует частичный снимок

#### Scenario: Перенаправление загрузки
- **WHEN** GitHub API возвращает HTTPS redirect на разрешённый хост загрузки GitHub
- **THEN** загрузка продолжается без переноса Authorization на другой origin

### Requirement: Различимые ошибки получения
Система MUST различать некорректный URL, недействительный токен, отсутствие доступа или репозитория, отсутствие ревизии, ограничение запросов, временную недоступность, недопустимый архив и локальный сбой хранения. Ошибка ограничения MUST предоставлять время повторения, если оно известно. Ошибки MUST NOT раскрывать токен и временный URL скачивания.

#### Scenario: Репозиторий недоступен
- **WHEN** GitHub отвечает 404 при чтении метаданных
- **THEN** возвращается «Репозиторий не найден или недоступен» без утверждения о его существовании

#### Scenario: Ограничение запросов
- **WHEN** ответ указывает на исчерпание лимита запросов
- **THEN** возвращается ошибка ограничения с доступным временем повторения без немедленного повторного запроса

#### Scenario: Временный сбой
- **WHEN** происходит timeout, ошибка соединения или ответ GitHub 5xx
- **THEN** возвращается временная ошибка без бесконечных повторов и без изменения состояния мониторинга

### Requirement: Получение исходников отдельно от анализа
Система MUST предоставлять снимок без извлечения зависимостей и присвоения статусов анализа. Получение исходников MUST NOT создавать успешный запуск мониторинга, изменять инвентарь зависимостей или трактовать отсутствие парсера как пустой результат.

#### Scenario: Парсер ещё не реализован
- **WHEN** вызывающий код успешно получил снимок проекта
- **THEN** исходники доступны, но записи зависимостей и оценки мониторинга не создаются и не заменяются
