# dependency-update-selection Specification

## Purpose

Связывать подтверждённую файлами текущую версию зависимости с последним стабильным неотозванным релизом PyPI и готовить явную пару версий для анализа изменений. Выбор сохраняет происхождение декларации и не является проверкой установки или совместимости.

## Requirements

### Requirement: Допуск текущей версии из инвентаря
Система MUST принимать одну декларацию инвентаря и обращаться к PyPI только для registry-зависимости с состоянием declared_pin или locked и корректной известной PEP 440 версией. Неизвестная, конфликтующая, неподдержанная или некорректная текущая версия MUST давать skipped с причиной и без сетевых обращений. Система MUST NOT разрешать диапазон для получения current.

#### Scenario: Диапазон без фиксации
- **WHEN** декларация содержит `httpx>=0.27,<1` с неизвестной текущей версией
- **THEN** результат skipped сообщает неизвестную текущую версию без запроса PyPI и без пары для анализа

#### Scenario: Конфликт или неподдержанный источник
- **WHEN** декларация содержит конфликт pins, direct URL или VCS
- **THEN** результат skipped сохраняет декларацию и соответствующую причину без сетевых обращений

#### Scenario: Ошибочная текущая версия
- **WHEN** состояние заявляет фиксацию, но current не является допустимой версией
- **THEN** результат skipped с причиной invalid_current не подменяет current версией из PyPI

### Requirement: Последний стабильный публичный релиз
Для допустимого входа система MUST сравнивать рекламируемые PyPI версии по PEP 440 и выбирать максимальную подходящую версию строго выше current. Prerelease, dev, local и некорректные версии MUST исключаться с причиной; post-релизы MUST допускаться. Порядок списка, написание эквивалентных версий и время публикации MUST NOT менять результат сравнения.

#### Scenario: Порядок и числовое сравнение
- **WHEN** PyPI отдаёт `2.9`, `3.0rc1`, `2.10`, `4.0.dev1` в произвольном порядке, а current равен `2.0`
- **THEN** подходящим максимальным кандидатом является `2.10`, а prerelease и dev исключены

#### Scenario: Post и epoch
- **WHEN** среди релизов есть `1!1.0`, `2.0`, `1!1.0.post1`, а current равен `2.0`
- **THEN** порядок PEP 440 определяет максимальным кандидатом `1!1.0.post1`

#### Scenario: Эквивалентные и некорректные строки
- **WHEN** индекс содержит `1`, `1.0`, повтор `1.0`, legacy-строку и чрезмерно длинный числовой компонент
- **THEN** эквивалентные версии проверяются однократно и детерминированно, а ошибочные строки сохраняются как исключения без аварийного прерывания выбора

### Requirement: Отозванный релиз не выбирается
Система MUST проверять metadata конкретного кандидата перед выбором. Кандидат с yanked MUST исключаться независимо от наличия текста причины; поиск MUST продолжаться по убыванию версии. Значение latest из metadata проекта MUST NOT заменять поиск по списку версий. Все успешно проверенные более новые кандидаты MUST быть исключены до выбора менее нового.

#### Scenario: Последний релиз отозван
- **WHEN** версии `3.0` и `2.0` новее current, metadata `3.0` сообщает yanked, а `2.0` — нет
- **THEN** выбран `2.0`, исключение `3.0` и причина отзыва сохранены в результате

#### Scenario: Отзыв без объяснения
- **WHEN** metadata кандидата имеет yanked=true с пустой причиной
- **THEN** кандидат всё равно исключается

#### Scenario: Все более новые стабильные релизы отозваны
- **WHEN** все стабильные кандидаты выше current успешно проверены и имеют yanked
- **THEN** результат no_update не содержит пары для анализа и сохраняет исключённые кандидаты

### Requirement: Единая политика MVP без фильтра совместимости
Выбор MUST использовать политику latest_stable без фильтра по specifier и constraints проекта, requires-python кандидата, платформе, extras или markers. Исходные ограничения и metadata выбранного релиза MUST сохраняться. Система MUST NOT оценивать markers по окружению LovoGit или заявлять, что выбранная версия допустима для установки.

#### Scenario: Target выходит за диапазон проекта
- **WHEN** проект объявляет `pkg<2`, current равен `1.5`, а последняя стабильная неотозванная версия равна `3.0`
- **THEN** выбрана `3.0`; ограничение `<2` сохранено, но не меняет target

#### Scenario: Другое требование Python
- **WHEN** последняя стабильная версия требует более новый Python, чем проект
- **THEN** она остаётся target, а её requires-python сохраняется для последующего анализа без поиска более старой совместимой версии

#### Scenario: Условная декларация
- **WHEN** входная декларация имеет marker или optional-область и известную текущую версию
- **THEN** выбор сохраняет её условия и область, не утверждая, что зависимость установлена в конкретном окружении

### Requirement: Отсутствие обновления не вызывает понижение версии
Если подходящих стабильных неотозванных релизов строго выше current нет, система MUST возвращать no_update с причиной и без запроса анализа. Она MUST NOT выбирать равную или более старую версию. При отсутствии более новых стабильных кандидатов уже по индексу дополнительные проверки metadata MUST NOT выполняться.

#### Scenario: Текущая версия уже последняя
- **WHEN** current=`1.0`, а максимальная стабильная версия индекса равна `1`
- **THEN** возвращается no_update без проверки metadata эквивалентного релиза и без запуска анализа

#### Scenario: Текущая версия выше публичной стабильной
- **WHEN** current новее всех стабильных версий индекса, включая случай текущего prerelease
- **THEN** возвращается no_update, а понижение до более старого стабильного релиза не предлагается

#### Scenario: Пустой индекс или только исключённые версии
- **WHEN** индекс не содержит допустимых более новых стабильных кандидатов
- **THEN** возвращается no_update с причиной и доступными исключениями, отдельно от skipped из-за неизвестного current

### Requirement: Результат выбора и явная пара версий
Обычный результат MUST содержать исходную декларацию, идентификатор политики, статус selected/no_update/skipped, причину, проверенные и исключённые версии. Только selected MUST содержать metadata выбранного target и запрос с нормализованным именем пакета, исходной строкой current и выбранной строкой target; сравнение MUST гарантировать current < target.

#### Scenario: Выбранное обновление
- **WHEN** для известного `httpx==0.27.2` выбран `0.28.0`
- **THEN** результат selected содержит пару `httpx`, `0.27.2`, `0.28.0`, metadata target и исходное provenance декларации

#### Scenario: Пара передаётся существующему сбору
- **WHEN** вызывающий передаёт сформированную пару в сбор материалов current/target
- **THEN** сбор получает именно эти две версии; сам выбор не загружает changelog и не вызывает LLM

### Requirement: Идентичность PyPI и ошибки чтения
Система MUST проверять соответствие нормализованного имени индекса и metadata входному пакету, а версии metadata — запрошенному кандидату по PEP 440. Несоответствие и ошибки чтения MUST передаваться вызывающему с контекстом пакета и версии, включая retry-after при наличии. Ошибки MUST NOT превращаться в no_update или скрытый выбор более старого релиза.

#### Scenario: Ошибка или исчезнувший кандидат
- **WHEN** чтение индекса или metadata завершается timeout, 404, 429, 5xx либо ошибкой схемы
- **THEN** вызывающий получает соответствующую ошибку, а результат «обновлений нет» и пара для более старого кандидата не создаются

#### Scenario: Metadata другого релиза
- **WHEN** запрошен кандидат `2.0`, но metadata сообщает другой пакет или версию `1.0`
- **THEN** выбор завершается ошибкой идентичности без запроса анализа

### Requirement: Ограниченный выбор с явным владением ресурсами
Операция MUST ограничивать общее время, включая чтение индекса, и число проверок metadata кандидатов. Исчерпание бюджета MUST давать отдельную ошибку с причиной и проверенными версиями, а отмена MUST передаваться вызывающему. Переданный сетевой клиент MUST оставаться под управлением вызывающего; немедленные повторные запросы после ошибки MUST NOT выполняться.

#### Scenario: Бюджет исчерпан до подходящего кандидата
- **WHEN** проверены максимально разрешённые кандидаты, все они отозваны, а остаются непроверенные
- **THEN** операция завершается ошибкой лимита, не объявляет no_update и не выбирает непроверенный релиз

#### Scenario: Последний кандидат проверен в пределах лимита
- **WHEN** последний разрешённый запрос завершил проверку всех кандидатов и все оказались yanked
- **THEN** no_update допустим, поскольку непроверенных кандидатов не осталось

#### Scenario: Отмена и клиент
- **WHEN** выбор отменён либо успешно завершён
- **THEN** отмена не скрывается и переданный клиент не закрывается операцией выбора

### Requirement: Выбор отдельно от выполнения мониторинга
Система MUST выполнять только чтение metadata PyPI и формирование результата в памяти. Она MUST NOT скачивать дистрибутивы и страницы, разрешать или устанавливать зависимости, выполнять тесты, исследовать код, изменять БД, инвентарь или состояние мониторинга. Результат MUST NOT присваивать оценку совместимости или означать автоматический запуск последующих этапов.

#### Scenario: Завершён только выбор
- **WHEN** target выбран
- **THEN** вызывающему доступна пара для следующего этапа, но файлы проекта, сохранённые оценки и состояние мониторинга неизменны
