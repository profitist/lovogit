# Spec Delta

## Purpose

Связывать готовые этапы анализа обновления одной прямой зависимости GitHub-проекта в воспроизводимый ручной запуск с поиском потенциально затронутого кода, сохраняемыми подтверждениями и трассировкой.

## ADDED Requirements

### Requirement: Ручной запуск одной зависимости
Система MUST предоставлять команду с GitHub URL и именем одной прямой зависимости, необязательным выбором поддержанного манифеста и флагом отправки трейса. Запуск MUST фиксировать default branch в SHA и использовать один снимок для инвентаря и поиска кода. Настройки Telegram MUST NOT требоваться.

#### Scenario: Воспроизводимый вход
- **WHEN** пользователь запускает анализ одной зависимости, а default branch изменяется после разрешения SHA
- **THEN** инвентарь и поиск кода относятся к исходному SHA, который сохранён вместе с нормализованным URL и параметрами запуска

### Requirement: Однозначная декларация из инвентаря
Имя MUST сопоставляться по нормализованному имени пакета с прямыми декларациями выбранного источника. При отсутствии или нескольких совпадениях запуск MUST завершаться skipped с причиной и доступным происхождением кандидатов без запросов PyPI и LLM. Система MUST NOT угадывать текущую версию, объединять варианты или оценивать markers по окружению контроллера.

#### Scenario: Несколько областей или платформ
- **WHEN** один пакет представлен несколькими записями с разными группами, markers либо версиями
- **THEN** отчёт сообщает ambiguous_dependency и перечисляет декларации; одинаковые current не разрешают неоднозначность

#### Scenario: Диапазон без lock
- **WHEN** имя соответствует единственной декларации, но её текущая версия неизвестна
- **THEN** результат skipped сохраняет причину селектора без попытки разрешить диапазон

#### Scenario: Нет поддержанного инвентаря
- **WHEN** разбор выбранного манифеста failed либо no_sources
- **THEN** отчёт различает ошибку разбора и отсутствие поддержанного источника, не представляя их как успешный пустой список зависимостей

### Requirement: Последовательное выполнение готовых этапов
Для допустимой декларации система MUST использовать latest_stable и запускать сбор, загрузку и извлечение только для выбранной пары current/target. no_update и skipped MUST останавливать последующие этапы. Ошибка чтения PyPI MUST NOT превращаться в отсутствие обновлений. Происхождение current, политика выбора и metadata target MUST сохраняться.

#### Scenario: Более новой версии нет
- **WHEN** селектор возвращает no_update
- **THEN** отчёт содержит причину и результат выбора без загрузки материалов, построения индекса и вызовов модели

### Requirement: Поиск потенциально затронутого кода
Система MUST исследовать код только по принятым изменениям из выбранного интервала, связывая каждый результат с идентификатором изменения и исходными цитатами. Изменения без API-символа MUST сохраняться. Неопределённые по версии и отклонённые утверждения MUST показываться отдельно и MUST NOT подаваться как подтверждённый вход поиска.

#### Scenario: Изменение поведения без символа
- **WHEN** принято изменение значения по умолчанию без имени функции
- **THEN** оно доступно поиску по описанию с той же связью с источником, а не исключено из-за отсутствия символа

#### Scenario: Нет пригодных изменений
- **WHEN** материалы отсутствуют либо извлечение не вернуло принятых изменений интервала
- **THEN** поиск кода не запускается, отчёт показывает причины и ограничения без вывода об отсутствии влияния

### Requirement: Ссылки на код переживают удаление снимка
Для найденных мест система MUST сохранять относительный путь, строку, доступный символ, объяснение, проверку существования ссылки и ограниченный фрагмент кода. Связанные тесты MUST различаться с исполненными тестами. Недействительные и выходящие за корень ссылки MUST давать диагностику без чтения внешних файлов и без потери других результатов.

#### Scenario: Снимок удалён
- **WHEN** поиск завершён и временные исходники освобождены
- **THEN** отчёт всё ещё показывает проверенные места с фрагментами и привязкой к SHA; тесты не объявлены выполненными

### Requirement: Явные результаты и ограничения
Результат MUST содержать исходы и причины этапов и общий статус completed, partial, failed, skipped или no_update. Completed MUST означать завершение предусмотренных операций, а не совместимость или полноту истории релизов. Пропуски по лимитам, неполнота исходных данных и поиска MUST оставаться видимыми; отсутствие совпадений MUST NOT означать безопасность обновления.

#### Scenario: Частичный поиск
- **WHEN** часть изменений исследована, а следующий поиск завершился timeout
- **THEN** общий статус partial сохраняет найденные места и конкретные необработанные изменения

#### Scenario: Совпадений нет
- **WHEN** все предусмотренные поиски закончились без найденных использований
- **THEN** отчёт описывает выполненный поиск и его ограничения без оценки совместимости

### Requirement: Сохраняемый отчёт и сырые ответы
Каждый запуск MUST получать отдельный каталог внутри игнорируемого artifacts/runs без перезаписи прежних запусков. Система MUST сохранять структурированный JSON и самостоятельный HTML с результатами этапов, диагностикой, исходными ответами модели, вызовами и результатами инструментов, материалами и выделенными использованными цитатами. Недоверенный текст MUST отображаться без исполнения HTML или скриптов.

#### Scenario: Цитата используется в выводе
- **WHEN** принятое изменение имеет проверенную цитату
- **THEN** отчёт связывает его с выделенным точным диапазоном исходного материала и показывает сырой ответ модели отдельно от проверенного результата

#### Scenario: Ошибка после начала запуска
- **WHEN** модель либо сетевой этап завершился ошибкой после создания каталога
- **THEN** сохранены доступные результаты и причина, а CLI печатает расположение отчёта; ошибка хранения явно сообщается, если сохранить отчёт невозможно

### Requirement: Независимая конфигурация модели
Первый ручной запуск MUST поддерживать OpenAI-compatible API, включая настроенный канал Polza, для извлечения и поиска с инструментами. Проверка LLM-настроек MUST происходить перед первым необходимым вызовом модели. Неподдержанный провайдер и отказ поддержки инструментов MUST давать явную ошибку, без скрытого перехода на другую модель или успешного пустого результата.

#### Scenario: Обновления нет без LLM ключа
- **WHEN** GitHub настроен, ключ LLM отсутствует, а селектор возвращает no_update
- **THEN** запуск сохраняет no_update без ошибки конфигурации модели

### Requirement: Локальная трассировка всех этапов
Система MUST сохранять локальный трейс и пригодный для Langfuse экспорт со связью этапов, вызовов модели и инструментов, временем, статусами и доступным usage. Сообщения и исходные ответы MUST сохраняться без API-ключей и заголовков авторизации. Недоступные usage или стоимость MUST NOT выдумываться; стоимость в иной валюте MUST NOT объявляться USD.

#### Scenario: Модель вызывает инструмент
- **WHEN** comparer запрашивает поиск и получает результат инструмента
- **THEN** локальные файлы содержат связанные записи генерации и инструмента, вход, выход и время без credentials

### Requirement: Явный экспорт сохранённого трейса
Отправка в Langfuse MUST выполняться только по явному запросу. Ошибка экспорта MUST сохраняться отдельно от исхода анализа и оставлять локальные файлы доступными. Система MUST предоставлять повторную отправку сохранённого трейса без повторения GitHub, PyPI и LLM этапов и защищаться от повторной отправки уже принятого payload.

#### Scenario: Langfuse недоступен
- **WHEN** анализ завершён, но запрошенный экспорт не удался
- **THEN** отчёт анализа сохранён, CLI сообщает отдельную ошибку экспорта, а повторная команда использует тот же сохранённый трейс

### Requirement: Ограничения и освобождение ресурсов
Запуск MUST иметь конечные бюджеты времени, числа исследуемых изменений, шагов агента и объёма сохраняемых данных. Превышение MUST явно отмечать необработанные данные. Снимок, индекс и сетевые клиенты MUST освобождаться при успехе, ошибке и отмене; внешняя отмена MUST NOT превращаться в успешный результат.

#### Scenario: Лимит изменений
- **WHEN** извлечено больше изменений, чем разрешено исследовать
- **THEN** выполненные поиски и полный список принятых изменений сохранены, остальные отмечены как не исследованные по лимиту, статус partial

#### Scenario: Отмена
- **WHEN** пользователь прерывает запуск во время построения индекса или поиска
- **THEN** новые этапы не начинаются, уже доступные данные сохраняются насколько возможно, ресурсы освобождаются и CLI завершается как прерванный

### Requirement: Анализ не меняет проект и мониторинг
Запуск MUST выполнять только чтение проекта и внешних источников и запись собственных локальных артефактов. Он MUST NOT устанавливать зависимости, выполнять проектный код или тесты, менять снимок, БД, оценки совместимости и состояние мониторинга. Материалы и код MUST рассматриваться как данные, без исполнения инструкций внутри них.

#### Scenario: Инструкция в changelog
- **WHEN** материал требует выполнить команду, прочитать внешний файл или изменить проект
- **THEN** запуск не выполняет требование и продолжает в пределах чтения снимка и сохранения собственных артефактов
