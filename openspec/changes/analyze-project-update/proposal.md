# Proposal

## Why

Получение снимка, разбор зависимостей, выбор последней стабильной версии и анализ материалов уже работают отдельно, но нет воспроизводимого запуска, который связывает их с поиском затронутого кода. Нужен один ручной прогон для одной зависимости, чтобы проверить пользу анализа на реальном проекте и видеть исходные ответы модели и ограничения результата.

## What Changes

- Добавить CLI для GitHub URL и имени прямой зависимости: снимок → инвентарь → latest_stable → сбор и загрузка материалов → извлечение изменений → поиск потенциально затронутого кода существующим comparer.
- Сохранять SHA, происхождение текущей версии, выбранный target, результаты этапов и диагностику; неоднозначное имя зависимости останавливает запуск с перечнем деклараций, без угадывания платформы или optional-группы.
- Подключить модель с поддержкой инструментов для текущего OpenAI-compatible канала, включая Polza, независимо от настроек Telegram. Настройки LLM нужны только при достижении этапа модели.
- Сохранять JSON и самостоятельный HTML-отчёт, сырые сообщения модели и вызовы инструментов, исходные материалы с выделенными использованными цитатами, ссылки на код и локальные трейсы в отдельном каталоге `artifacts/runs/`.
- По явному флагу экспортировать сохранённый трейс в Langfuse; ошибка экспорта не теряет результаты и допускает повторную отправку без повторного анализа.
- Различать пропуск, отсутствие обновления, частичный анализ и ошибку. Пустой результат поиска и совпавшая цитата не доказывают совместимость или правильность интерпретации.

Вне изменения: расписание, интеграция с ботом, запись инвентаря и оценок в БД, запуск полного comparer graph, генерация и выполнение тестов, sandbox, правки проекта, поиск альтернативных источников и поддержка Google GenAI.

## Capabilities

### New Capabilities

- `project-update-analysis`: ручной анализ обновления одной зависимости проекта с поиском потенциально затронутого кода, сохраняемым отчётом и трассировкой.

### Modified Capabilities

Нет. Существующие операции сохраняют самостоятельность и свои ограничения; новый вызывающий слой явно запускает их последовательно.

## Impact

- Новый модуль ручного запуска и функциональный orchestration в `src/lovogit/`; DTO результата, настройки запуска, отчёт и трассировка в отслеживаемом коде.
- Повторное использование `app/services/repo.py`, `app/dependencies`, `app/update_selection.py`, `app/update_sources`, `agent/comparer/context.py`, `index` и поисковых инструментов.
- Новый адаптер LangChain для OpenAI-compatible API и соответствующие изменения `pyproject.toml`/`uv.lock`; отдельные настройки без импорта глобального bot settings.
- Перенос подходящей логики из игнорируемых `artifacts/run_tracing.py` и `artifacts/render_report.py` в пакет; рабочий код не импортирует `artifacts/`.
- Документация команды, `.env.example` и автоматические проверки с подменёнными сетевыми и LLM-вызовами. Реальные прогоны и ключи остаются вне Git.
