# Spec Delta

## Purpose

Извлекать зависимости корневого Python-проекта из снимка исходников и определять подтверждённые файлами версии, сохраняя ограничения, происхождение и причины неизвестности. Результат служит входом последующего мониторинга и не доказывает состав установленного окружения.

## ADDED Requirements

### Requirement: Детерминированный выбор источника
Система MUST обнаруживать корневые `pyproject.toml`, `requirements.txt` и `uv.lock`. По умолчанию декларации MUST читаться из `pyproject.toml` с таблицей `project`, иначе из `requirements.txt`. Вызывающий MUST иметь возможность явно выбрать один из двух источников. Источники MUST NOT автоматически объединяться; вложенные проекты MUST NOT обнаруживаться рекурсивно.

#### Scenario: Оба манифеста
- **WHEN** корень содержит PEP 621 проект и `requirements.txt`
- **THEN** автоматически выбран pyproject, а requirements отмечен как невыбранный; его зависимости не добавлены в инвентарь

#### Scenario: Явный выбор requirements
- **WHEN** вызывающий явно выбирает requirements при наличии обоих манифестов
- **THEN** разобран `requirements.txt` с его включениями, а `uv.lock` не используется для определения версий этого источника

#### Scenario: Неподдержанный проект
- **WHEN** есть только `setup.py`, секции Poetry либо вложенный проект без поддержанного корневого манифеста
- **THEN** результат сообщает отсутствие поддержанного источника и доступную диагностику, а не успешный пустой инвентарь

### Requirement: Результат связан со снимком
Инвентарь MUST сохранять идентичность репозитория и commit SHA, выбранный источник, список обнаруженных и прочитанных файлов, декларации, ограничения и диагностику. Происхождение каждой записи MUST содержать относительный путь и строку requirements либо ключ TOML. Результат MUST быть доступен после освобождения временного снимка без повторного чтения файлов.

#### Scenario: Снимок закрыт
- **WHEN** разбор выполнен внутри контекста получения исходников, а временный каталог затем удалён
- **THEN** имена, версии, причины и места деклараций остаются доступны вместе с SHA снимка

### Requirement: Статический разбор PEP 621
Система MUST разбирать `project.dependencies` и `project.optional-dependencies` как декларации PEP 508 с нормализованными именами, extras, specifier и marker. Обязательные зависимости и каждая optional-группа MUST различаться. Отсутствующее статическое поле MUST означать пустой список, а объявленное dynamic поле MUST означать неизвестное содержимое без выполнения build backend.

#### Scenario: Обязательная и optional зависимость
- **WHEN** `httpx>=0.27` находится в dependencies, а `pytest>=8` — в optional-группе test
- **THEN** обе декларации сохранены с разными областями, а optional-группа не представлена как установленная или обязательная

#### Scenario: Динамические зависимости
- **WHEN** `project.dynamic` включает dependencies
- **THEN** результат отмечен как неполный с причиной динамических зависимостей и не объявляет обязательные зависимости отсутствующими

#### Scenario: Другие секции
- **WHEN** pyproject содержит build-system.requires или dependency-groups
- **THEN** они не становятся runtime-зависимостями; dependency-groups отмечены как вне поддержанного охвата, а build-system не исполняется

### Requirement: Поддержанное подмножество requirements
Система MUST разбирать именованные PEP 508 требования в UTF-8 requirements, пустые строки, комментарии, продолжения строк и повторяющиеся `--hash`. Локальные `-r`/`--requirement` MUST добавлять декларации, а `-c`/`--constraint` MUST добавлять только ограничения. Ссылки MUST разрешаться относительно включающего файла; цикл и отсутствующий файл MUST давать диагностику.

#### Scenario: Включение и продолжение строки
- **WHEN** корневой requirements включает `requirements/base.txt`, содержащий многострочный pin с hash и marker
- **THEN** декларация разобрана один раз в соответствующем контексте и сохраняет путь, диапазон строк, marker и hash без установки или проверки дистрибутива

#### Scenario: Только constraint
- **WHEN** constraint содержит `urllib3==2.2.3`, но ни один requirements не требует urllib3
- **THEN** constraint сохранён отдельно, а urllib3 не появляется как зависимость проекта

#### Scenario: Constraint уточняет диапазон
- **WHEN** requirements требует `httpx>=0.27,<1`, а его безусловный constraint задаёт `httpx==0.28.0`
- **THEN** версия отмечена как объявленная фиксация из совместного требования и constraint с обоими местами происхождения

#### Scenario: Неподдержанная директива
- **WHEN** встречена неизвестная опция, удалённое включение либо подстановка переменной окружения
- **THEN** она не исполняется и не игнорируется молча: результат содержит диагностику неполного разбора

### Requirement: Условия не вычисляются по окружению контроллера
Система MUST сохранять markers и extras без оценки на машине LovoGit. Условные декларации MUST оставаться условными; ограничения с разными условиями MUST NOT безусловно пересекаться. Разные варианты одного имени MUST сохраняться отдельно вместе с областью применимости. Эта версия функции MUST NOT утверждать конкретный состав окружения.

#### Scenario: Две платформы
- **WHEN** requirements содержит разные pins одного пакета для Windows и Linux
- **THEN** сохранены оба условных варианта без выбора платформы контроллера и без объявления безусловного конфликта

#### Scenario: Условный constraint
- **WHEN** безусловное требование имеет constraint с marker платформы
- **THEN** условие сохранено, а ограничение не превращается в единственную безусловно используемую версию

### Requirement: Фиксация отличается от диапазона
Каждая декларация MUST различать подтверждённую фиксацию `declared_pin`, версию из lock `locked`, неизвестность `unresolved`, конфликт `conflict` и неподдержанный источник `unsupported`. `current_version` MUST присутствовать только при однозначной фиксации с происхождением. Диапазон, wildcard и отсутствие specifier MUST NOT заменяться нижней, верхней или последней опубликованной версией.

#### Scenario: Диапазон без lock
- **WHEN** объявлено `httpx>=0.27,<1`, а применимого lock нет
- **THEN** сохранены диапазон, состояние unresolved, причина отсутствия однозначной фиксации и `current_version = null`

#### Scenario: Pin и wildcard
- **WHEN** одно требование использует `==0.28.0`, а другое — `==0.28.*`
- **THEN** первое имеет declared_pin при отсутствии противоречий, а второе остаётся unresolved без применимого lock

#### Scenario: Несовместимые pins
- **WHEN** безусловные требования и constraints одной области задают несовместимые точные версии одного нормализованного имени
- **THEN** результат содержит conflict и все места происхождения без выбранной текущей версии

### Requirement: Ограниченная поддержка uv.lock
Система MUST читать `uv.lock` только для выбранного pyproject-проекта и документированного поддержанного формата. Проверка MUST включать корневую запись проекта, соответствие его деклараций metadata lock и ограничения requires-python. Неизвестный формат, workspace или влияющие на разрешение неподдержанные настройки MUST оставлять версии неподтверждёнными с диагностикой, без запуска uv.

#### Scenario: Согласованный lock
- **WHEN** диапазон прямой зависимости соответствует metadata корневого проекта, а lock содержит единственную подходящую registry-версию
- **THEN** декларация получает locked с версией и ссылками на манифест и запись lock

#### Scenario: Изменённый манифест
- **WHEN** pyproject изменён относительно metadata корневой записи lock, даже если прежняя версия ещё входит в новый диапазон
- **THEN** lock отмечен как несогласованный и не подтверждает текущую версию; прежняя запись сохранена только как кандидат

#### Scenario: Неподдержанный формат
- **WHEN** версия или revision lock не поддержаны либо lock принадлежит workspace
- **THEN** результат явно сообщает ограничение, не выбирает версию из lock и не запускает его обновление

### Requirement: Кандидаты lock не подменяют состав проекта
Система MUST сопоставлять registry-записи lock с прямыми декларациями и их областями. Транзитивные пакеты и сам проект MUST NOT становиться прямыми зависимостями. При нескольких вариантах MUST сохраняться кандидаты и их условия; единственная версия допустима только при доказанной применимости в пределах поддержанного разбора. Отсутствие записи или несовместимость MUST иметь явную причину.

#### Scenario: Несколько версий в универсальном lock
- **WHEN** прямому требованию соответствуют версии пакета для разных Python или платформ, а их нельзя свести к одной применимой версии
- **THEN** результат unresolved с кандидатами и markers, а первая или наибольшая версия не выбирается

#### Scenario: Транзитивная зависимость
- **WHEN** lock содержит httpcore, но проект явно объявляет только httpx
- **THEN** httpcore не добавляется в список прямых деклараций

#### Scenario: Lock противоречит pin
- **WHEN** pyproject требует точный pin, а сопоставленная запись lock ему противоречит
- **THEN** версия не публикуется как подтверждённая; результат сохраняет конфликт или несогласованность и оба источника

### Requirement: Неподдержанные источники сохраняют неизвестность
Именованные direct URL, VCS, локальные и editable зависимости MUST сохраняться как декларации с неподдержанным источником; их версия MUST NOT выводиться из URL, имени файла или поля version локального проекта. Неименованные записи MUST оставаться в диагностике без выдуманного имени. Poetry, Pipenv и setup.py MUST NOT исполняться или интерпретироваться как PEP 621.

#### Scenario: Git или локальная ссылка
- **WHEN** объявлено именованное требование Git либо локальная editable установка
- **THEN** результат сохраняет доступные данные и причину unsupported без подтверждённой текущей версии

### Requirement: Полнота разбора отделена от известности версии
Инвентарь MUST иметь статус `complete`, `partial`, `failed` или `no_sources`. Complete MUST означать полный разбор поддержанного выбранного источника, но не известность всех версий. Пропуски и неподдержанные записи MUST давать partial; невозможность разобрать выбранный корневой файл — failed. Отсутствие подходящего источника MUST давать no_sources, а известный пустой список — complete.

#### Scenario: Пустой проект и неизвестный диапазон
- **WHEN** статический список зависимостей пуст либо содержит только корректный диапазон без lock
- **THEN** статус complete; в первом случае деклараций нет, во втором зависимость присутствует с неизвестной версией

#### Scenario: Ошибка одного требования
- **WHEN** одна строка requirements неверна, а остальные требования корректны
- **THEN** корректные декларации доступны, статус partial и диагностика указывает путь и строку ошибки

#### Scenario: Неверный корневой TOML
- **WHEN** автоматически выбранный pyproject синтаксически неверен, а рядом есть requirements
- **THEN** результат failed без скрытого переключения на requirements

### Requirement: Ограниченное чтение снимка
Чтение MUST оставаться внутри корня снимка, отклонять symlink и специальные файлы и иметь документированные лимиты числа файлов, глубины включений, прочитанных байтов и записей. Выход пути за корень, цикл и превышение лимита MUST быть различимы в диагностике; частичный результат MUST NOT выглядеть полным.

#### Scenario: Включение за пределами снимка
- **WHEN** `-r` указывает наружу, на symlink или удалённый ресурс
- **THEN** внешний ресурс не читается, а результат содержит диагностику запрещённого включения

#### Scenario: Цикл или большой файл
- **WHEN** цепочка включений зациклена либо достигнут лимит
- **THEN** обработка ограниченно завершается с конкретной причиной и неполным или ошибочным результатом

### Requirement: Разбор не меняет проект и мониторинг
Разбор MUST выполнять только чтение снимка и возвращать результат в памяти. Он MUST NOT обращаться к сети, вызывать LLM, устанавливать зависимости, выполнять проектный код, читать установленное окружение контроллера, менять снимок, БД или состояние мониторинга. Pin и lock MUST описываться как сведения из файлов, а не доказательство установки, импорта или совместимости.

#### Scenario: Успешное извлечение
- **WHEN** зависимости и их фиксации определены по снимку
- **THEN** исходники и таблицы остаются неизменными, а результат доступен отдельно от статусов мониторинга и анализа совместимости
