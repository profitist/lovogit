# Proposal

## Why

`UpdateSourceService` собирает метаданные двух релизов и опубликованные ссылки, но содержимое changelog и release notes пока недоступно последующему анализу. Нужен отдельный ограниченный загрузчик, который сохраняет происхождение материалов и различает отсутствие ссылок, отказ загрузки и полученный текст.

## What Changes

- Добавить отдельный асинхронный сервис загрузки явно обозначенных changelog/release_notes из готового `UpdateSourcesDTO`.
- Возвращать текст HTML, Markdown и plain text с исходным URL, конечным адресом, content type и всеми ссылками на происхождение.
- Ограничить сетевые назначения, редиректы, время, число запросов и размер ответа; исключить передачу credentials и доступ к внутренним адресам.
- Сохранять отдельный результат каждой ссылки, включая пропуск, сетевую ошибку и успешную загрузку; ошибки одного источника не скрывают остальные.
- Сохранить сбор метаданных самостоятельным: он по-прежнему не загружает страницы. Поиск дополнительных источников, обход ссылок, извлечение секций релизов, LLM, comparer, БД и бот остаются за рамками этого change.

## Capabilities

### New Capabilities

- `update-source-fetching`: ограниченная загрузка опубликованных источников изменений с происхождением и явными результатами доступности.

### Modified Capabilities

Нет. Требования `update-source-collection`, включая отсутствие сетевых обращений к опубликованным ссылкам при сборе метаданных, сохраняются.

## Impact

- Новые сервис/DTO в `src/lovogit/app/services/`, HTTP-загрузчик в `app/providers/`, независимые настройки в `cfg/`.
- Используется существующий `httpx`; транспорт должен связывать проверенное разрешение DNS с фактическим соединением. Если для этого потребуется прямая зависимость на `httpcore`, она объявляется явно.
- Новые тесты с подменой сети и документация в `docs/pypi.md`; существующий публичный API сбора и состояние мониторинга не меняются.
