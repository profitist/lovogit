# Spec Delta

## Purpose

Предоставлять содержимое опубликованных источников изменений для последующего анализа обновления, сохраняя происхождение материалов и явно обозначая ограничения и ошибки загрузки.

## ADDED Requirements

### Requirement: Явный запуск загрузки
Система MUST принимать готовый результат сбора двух релизов и загружать только подходящие ссылки changelog/release_notes. Остальные ссылки MUST сохраняться как пропущенные с причиной без сетевого обращения. Отсутствие подходящих ссылок MUST отличаться от ошибки загрузки. Сбор метаданных MUST оставаться независимым от загрузки.

#### Scenario: Только документация
- **WHEN** у обоих релизов есть только source и documentation
- **THEN** загрузчик возвращает пропуски и отсутствие кандидатов, не выполняя запросов

#### Scenario: Исключённая ссылка
- **WHEN** changelog имеет причину исключения при сборе
- **THEN** ссылка сохраняется как пропущенная с этой причиной и не запрашивается

### Requirement: Происхождение и повторяющиеся ссылки
Система MUST сохранять исходные ссылки, labels, категории и происхождение current/target, конечный URL, цепочку редиректов и доступный HTTP-контекст. Совпадающие адреса без fragment MUST загружаться однократно в рамках вызова с сохранением всех исходных ссылок. Различные query MUST оставаться различными адресами.

#### Scenario: Общий changelog
- **WHEN** обе версии указывают один URL с разными fragment
- **THEN** выполняется одна загрузка и результат ссылается на обе исходные записи с сохранёнными fragment

### Requirement: Проверка сетевых назначений
Система MUST проверять каждый начальный URL и редирект: разрешены только HTTP(S), стандартные порты, отсутствие credentials и публичные адреса назначения. Непубличные IP, localhost и смешанные публичные/непубличные DNS-ответы MUST блокироваться до соединения. Фактическое соединение MUST использовать проверенный IP без повторного непроверенного DNS-разрешения.

#### Scenario: Редирект во внутреннюю сеть
- **WHEN** публичная страница перенаправляет на loopback, private, link-local или служебный адрес
- **THEN** загрузка завершается результатом blocked_destination без обращения к этому адресу

#### Scenario: Изменение DNS
- **WHEN** после проверки DNS имя начинает разрешаться во внутренний адрес
- **THEN** соединение использует только ранее проверенное публичное назначение либо блокируется

### Requirement: Изоляция HTTP-запросов
Система MUST выполнять анонимные GET без cookies, авторизации, настроек proxy из окружения и credentials экземпляра. Редиректы MUST обрабатываться явно с повторной проверкой назначения; HTTPS MUST NOT понижаться до HTTP. Система MUST проверять TLS-сертификаты и не выполнять автоматические повторы.

#### Scenario: Cookies и смена домена
- **WHEN** ответ устанавливает cookie и перенаправляет на другой публичный домен
- **THEN** следующий запрос не содержит cookie или credentials, а новое назначение проверяется заново

### Requirement: Ограничение ресурсов
Система MUST ограничивать число уникальных загрузок, число редиректов, время каждой загрузки вместе с DNS, общий срок вызова и размер полученного тела. При превышении лимита результат MUST содержать отдельную причину без усечённого успешного текста. Оставшиеся ссылки MUST получить результат пропуска по лимиту; открытые ответы MUST закрываться.

#### Scenario: Превышен размер
- **WHEN** поток ответа превышает лимит, даже без Content-Length
- **THEN** чтение останавливается, ответ закрывается и источник получает size_limit без текста

#### Scenario: Исчерпан общий срок
- **WHEN** общий срок вызова истекает во время загрузки
- **THEN** текущий источник получает timeout, оставшиеся получают deadline_exceeded, а готовые результаты сохраняются

### Requirement: Текст материалов
Система MUST принимать только HTTP 200 с text/plain, text/markdown или text/html и сохранять декодированный текст без извлечения секций и выполнения HTML. Неподдерживаемый тип, кодировка, ошибка декодирования и пустой текст MUST иметь явную причину без успешного материала. Успешная загрузка MUST NOT означать подтверждение соответствия текста выбранным релизам.

#### Scenario: HTML со скриптом
- **WHEN** источник возвращает HTML changelog со скриптом
- **THEN** HTML сохраняется как недоверенный текст без выполнения скриптов и запросов вложенных ресурсов

#### Scenario: Ошибочное содержимое
- **WHEN** ответ имеет неподдерживаемый тип либо содержит только пробелы
- **THEN** возвращается unsupported_content_type либо empty_content без успешного текста

### Requirement: Независимые результаты и отмена
Система MUST возвращать fetched, skipped или failed для каждого источника, сохраняя доступные status code и Retry-After. Ошибка одного источника MUST NOT скрывать остальные или означать отсутствие изменений. Отмена вызывающим MUST передаваться без преобразования. Загрузчик MUST NOT вызывать анализ, записывать состояние или присваивать совместимость.

#### Scenario: Частичная доступность
- **WHEN** один источник возвращает 429, а другой доступен
- **THEN** первый получает failed с кодом и Retry-After, второй содержит материал, повторов нет

#### Scenario: Отмена вызова
- **WHEN** вызывающий отменяет загрузку
- **THEN** отмена передаётся вызывающему, текущий ответ закрывается и новые запросы не запускаются
