# Design

## Context

Мотивация — в `proposal.md`. `commands.py` регистрирует заглушку `/attention` в общем роутере раньше защищённого роутера `/status`. `StatusService.get_overview()` читает последний запуск и успешный снимок одним SQL-запросом, но возвращает только счётчики. `DependencyResult` уже хранит все нужные для списка поля. Данных о причинах анализа, затронутом коде и официальных источниках в этой таблице нет.

`StatusMiddleware` проверяет чат до открытия сессии и внедряет `StatusService`; `status_format.py` содержит русские названия, UTC-форматирование и разбиение по UTF-16. `tests/test_status_service.py` покрывает удаление проектов и выбор снимка при конкурирующих запусках. Эти решения задают образец реализации. Изменение затрагивает сервис, доступ и маршрутизацию, поэтому нужен отдельный дизайн.

## Goals / Non-Goals

**Goals:** согласованное чтение происхождения снимка и его результатов, использование уже проверенных правил доступа и форматирования, сохранение контракта `/status`.

**Non-Goals:** вычисление оценок, извлечение зависимостей, изменение инвентаря, дополнение модели отчётами или настройка Mini App. `src/lovogit/agent/` и агентская документация не меняются.

## Decisions

### Отдельный сервис чтения с одним запросом

Добавить `AttentionService` и неизменяемые DTO проекта/зависимости в `app/services/attention.py`. DTO проекта содержит ID, имя, последний запуск (`CheckSummaryDTO`), ID и время успешного снимка и список выбранных результатов. Для ошибок чтения определить `AttentionUnavailable` с сохранением причины.

Использовать коррелированные подзапросы выбора запусков по образцу `StatusService`, внешнее соединение результатов выбранного снимка с фильтром статусов в условии JOIN. Это сохраняет проекты без снимка и без совпадений. Один запрос возвращает согласованные метаданные и строки, группируемые в DTO; число запросов не растёт с числом проектов. Альтернатива — `get_overview()` и отдельные запросы на пакеты — добавляет лишние счётчики и риск чтения разных снимков между запросами.

Источником списка является сохранённый снимок, а не текущий `RepoDependency`: не пересекать его с изменившимся инвентарём. Все версии относятся к указанному времени снимка. Приоритет статусов задать явно; даты возвращать с UTC через существующий `as_utc`.

### Изолированный защищённый роутер

Добавить `bot/attention.py`, `attention_format.py` и небольшой `AttentionMiddleware` по образцу защищённого `/status`, внедряющий только `AttentionService`. Не обобщать действующий middleware ради двух команд: это отдельный рефакторинг. Удалить только регистрацию и тело заглушки `/attention` из `commands.py`, подключить новый роутер в `bot.py`. Проверить полный Dispatcher с общим роутером: старый обработчик иначе перехватит команду до проверки доступа.

### Текстовое представление без фиктивных подробностей

Переиспользовать `STATUS_LABELS`, `format_time` и `split_messages`. Форматировать отдельный блок каждого проекта и все строки зависимостей, отправлять с `parse_mode=None`. Не добавлять полей, которых нет в хранилище; неизвестная версия — «неизвестна». Исключения Telegram не маскировать под ошибку БД.

В `docs/dev-docs.md` явно обозначить отклонение первого рабочего `/attention` от целевого интерфейса: текстовое ограничение анализа вместо ссылки, без кнопки «Подробнее». Настоящие ссылки зависят от отсутствующих API, адреса и выбора проекта в Mini App; добавление их сейчас расширило бы задачу до другого подсистемного изменения. Сохранить их в документации как последующий этап. `/help` описывает `/attention` как просмотр сохранённых результатов.

## Risks / Trade-offs

- Сохранённые результаты могут устареть после изменения инвентаря → время снимка обязательно; новая ошибка или выполняющийся запуск сопровождаются предупреждением.
- До появления исполнителя мониторинга список обычно пуст → отсутствие оценок сообщается явно, без фиктивных результатов.
- Дублирование небольшого middleware → ограничить копирование проверкой доступа и жизненным циклом сессии, проверить отсутствие регрессий `/status`.
- Большой список создаёт несколько сообщений → использовать проверенный splitter и проверять полный текст, порядок и emoji; пагинация в этот этап не входит.
- Документация обещает подробности → зафиксировать этапность в документации команд; не изменять описания агентского конвейера.

## Migration Plan

Миграций БД и новых настроек нет. Развернуть код с существующим `ALLOWED_CHAT_IDS`; проверить отказ неразрешённому чату и чтение заранее сохранённого снимка. Откат версии возвращает заглушку, не меняя историю мониторинга. Проверки и маршрутизация `/status` должны сохраниться.
