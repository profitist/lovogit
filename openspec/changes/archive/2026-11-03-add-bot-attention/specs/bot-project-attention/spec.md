# Spec Delta

## Purpose

Позволять участникам разрешённых чатов просматривать сохранённые оценки зависимостей, требующих внимания, по всем проектам экземпляра без запуска анализа.

## ADDED Requirements

### Requirement: Доступ по чату
Команда `/attention` MUST проверять chat_id по списку разрешённых чатов до открытия сессии БД. Пустой список MUST запрещать доступ. Все участники разрешённых чатов MUST видеть один набор проектов.

#### Scenario: Отказ в доступе
- **WHEN** чат не разрешён либо список разрешений пуст
- **THEN** бот отвечает «Нет доступа», не открывая сессию БД

#### Scenario: Общий доступ
- **WHEN** разные участники разрешённых чатов запрашивают `/attention` при одинаковом состоянии БД
- **THEN** они получают одинаковый набор проектов и результатов

### Requirement: Выбор результатов
Команда MUST только читать данные неудалённых проектов и показывать результаты `incompat`, `review`, `failed` последнего успешного снимка каждого проекта. Снимок MUST выбираться по убыванию времени начала запуска, затем ID. Другие статусы и результаты иных запусков MUST NOT попадать в список.

#### Scenario: Смешанные статусы и проекты
- **WHEN** есть активные и удалённые проекты и снимки со всеми шестью статусами
- **THEN** показаны только три требующих внимания статуса активных проектов, сгруппированные по проекту

#### Scenario: Обратный порядок завершения
- **WHEN** более старый запуск завершён после более нового успешного запуска
- **THEN** показаны результаты более нового по времени начала запуска

#### Scenario: Равное время начала
- **WHEN** два успешных запуска имеют одинаковое время начала
- **THEN** используется снимок запуска с большим ID

### Requirement: Содержание и порядок
Для каждого проекта команда MUST показывать имя, ID и время успешного снимка в UTC, а для каждой найденной зависимости — имя, текущую и последнюю версии и русский статус. Неизвестная последняя версия MUST обозначаться «неизвестна». Проекты MUST сортироваться по имени и ID, зависимости — по приоритету `incompat`, `review`, `failed`, затем имени.

#### Scenario: Одинаковые пакеты в разных проектах
- **WHEN** один пакет требует внимания в двух проектах
- **THEN** оба результата показаны отдельно в своих проектах с версиями и временем снимка

#### Scenario: Неизвестная версия
- **WHEN** у результата отсутствует последняя версия
- **THEN** вместо неё показано «неизвестна», без выдуманного номера

### Requirement: Актуальность данных
Команда MUST отличать последний запуск от успешного снимка. Если последний запуск выполняется или неудачен, команда MUST показать это состояние, причину ошибки при неудаче и предупреждение, что оценки предыдущей успешной проверки могут быть устаревшими.

#### Scenario: Новая ошибка или выполняющаяся проверка
- **WHEN** после успешного снимка начат новый запуск, который выполняется либо завершился ошибкой
- **THEN** предыдущие результаты сохранены в ответе со временем снимка, состоянием нового запуска и предупреждением об устаревании

### Requirement: Пустые и неизвестные результаты
При отсутствии успешного снимка команда MUST сообщать «Оценки обновлений пока нет». При наличии снимка без выбранных статусов MUST сообщать «По этому снимку зависимостей, требующих внимания, нет». При отсутствии проектов MUST сообщать «Проекты не настроены» и пояснять настройку при развёртывании. Состояния MUST показываться отдельно по каждому проекту.

#### Scenario: Нет успешной проверки
- **WHEN** запусков нет либо существуют только выполняющиеся или неудачные запуски
- **THEN** ответ не утверждает отсутствие проблем и сообщает об отсутствии оценок с состоянием последнего запуска, если он есть

#### Scenario: Пустой либо спокойный снимок
- **WHEN** успешный снимок пуст либо содержит только `waiting`, `low`, `current`
- **THEN** ответ сообщает об отсутствии требующих внимания зависимостей именно по этому снимку

#### Scenario: Смешанное состояние проектов
- **WHEN** один проект без оценок, у другого есть выбранные зависимости, а у третьего их нет
- **THEN** ответ содержит все три проекта с соответствующими состояниями

#### Scenario: Нет проектов
- **WHEN** неудалённые проекты отсутствуют
- **THEN** ответ сообщает об отсутствии настроенных проектов и способе подключения при развёртывании

### Requirement: Ограничение интерпретации
Ответ с оценками MUST содержать пояснение «Отсутствие требующих внимания зависимостей не гарантирует совместимость; ожидающие анализа зависимости ещё не оценены». Команда MUST NOT показывать неработающие ссылки и кнопки подробностей.

#### Scenario: Снимок без тревожных статусов
- **WHEN** снимок содержит низкорисковые или ожидающие анализа зависимости
- **THEN** ответ содержит ограничение интерпретации без обещания совместимости и без неработающей кнопки

### Requirement: Ошибка чтения
При технической ошибке чтения команда MUST отвечать «Не удалось получить список зависимостей. Попробуйте позже» без SQL, секретов и частичной сводки. Подробности MUST сохраняться в журнале. Ошибка мониторинга отдельного проекта MUST оставаться данными и не скрывать остальные проекты.

#### Scenario: База недоступна
- **WHEN** чтение завершается технической ошибкой
- **THEN** отправлен нейтральный ответ, а подробности записаны в журнал

### Requirement: Полная текстовая доставка
Ответ MUST доставляться полностью и последовательно сообщениями не длиннее 4096 единиц UTF-16 каждое. Имена, версии и причины ошибок MUST передаваться обычным текстом без интерпретации HTML или Markdown. Команда MUST NOT запускать мониторинг или изменять хранимое состояние.

#### Scenario: Длинный ответ со специальными символами
- **WHEN** ответ превышает лимит и содержит emoji и символы разметки
- **THEN** весь текст доставлен в исходном порядке допустимыми сообщениями без интерпретации разметки

#### Scenario: Только чтение
- **WHEN** разрешённый чат вызывает команду
- **THEN** история запусков и снимков не меняется и новая проверка не запускается
