# Proposal

## Why

`/attention` пока отвечает заглушкой, хотя успешные снимки уже содержат имена, версии и статусы зависимостей. Пользователю нужен конкретный список требующих внимания пакетов вместо одних счётчиков `/status`; его можно получить без разработки агента.

## What Changes

- Реализовать чтение `/attention` по всем неудалённым проектам экземпляра: `incompat`, `review`, `failed` из последнего успешного снимка каждого проекта.
- Показывать проект и ID, время снимка, имя пакета, версии и русский статус; сохранять различие между отсутствием оценок и отсутствием требующих внимания пакетов.
- При новой выполняющейся или неудачной проверке явно обозначать предыдущие оценки как потенциально устаревшие.
- Проверять разрешённый чат до открытия БД, доставлять длинный ответ целиком обычным текстом, нейтрально обрабатывать ошибки чтения.
- Уточнить документацию: первый рабочий `/attention` текстовый. Предусмотренные в `docs/dev-docs.md` кнопка «Подробнее» и ссылка на границы анализа откладываются до появления рабочего Mini App API и адреса; вместо ссылки показывается текстовое ограничение анализа.

## Capabilities

### New Capabilities

- `bot-project-attention`: защищённый просмотр зависимостей, требующих внимания, с происхождением и актуальностью сохранённых оценок.

### Modified Capabilities

Нет. Контракты `bot-project-status` и `project-monitoring-state` сохраняются.

## Impact

Сервис чтения в `src/lovogit/app/services/`, обработчик, форматирование и маршрутизация в `src/lovogit/bot/`, тесты по образцу `tests/test_status_*.py`, документация команд. Используются существующие таблицы и зависимости; миграции и новые HTTP API не нужны. Агентская часть, провайдеры исходников, запуск мониторинга, планировщик, Mini App, `/dep` и `/check` исключены. Изменение читает уже сохранённые результаты и само их не создаёт.
