# Spec Delta

## Purpose

Позволять участникам разрешённых чатов регистрировать доступные GitHub-репозитории в общем списке отслеживаемых проектов без ручного изменения базы данных и без запуска анализа.

## ADDED Requirements

### Requirement: Общий доступ к регистрации
Команда `/add_repo` MUST проверять chat_id по списку разрешённых чатов до сети и открытия сессии БД. Пустой список MUST запрещать доступ. Любой участник разрешённого чата MUST иметь право добавлять проекты в общий список экземпляра.

#### Scenario: Неразрешённый чат
- **WHEN** команда приходит из неразрешённого чата либо список разрешений пуст
- **THEN** бот отвечает «Нет доступа» без сетевых запросов и обращения к БД

#### Scenario: Общий проект
- **WHEN** участник разрешённого чата добавляет репозиторий
- **THEN** проект доступен всем разрешённым чатам без привязки к добавившему пользователю

### Requirement: Формат команды
Команда MUST принимать ровно один HTTPS URL корня репозитория github.com с необязательными `.git` и завершающим `/`. Отсутствующие или лишние аргументы MUST давать подсказку `/add_repo <github-url>`. Другие схемы, хосты, credentials, query, fragment и внутренние пути MUST отклоняться до сети и записи в БД.

#### Scenario: Подсказка
- **WHEN** пользователь отправляет `/add_repo` без URL или с дополнительным аргументом
- **THEN** бот показывает формат команды и пример, не обращаясь к GitHub и не меняя БД

#### Scenario: Неверный адрес
- **WHEN** передан SSH URL, адрес другого хоста либо файла репозитория
- **THEN** бот сообщает о необходимости HTTPS URL корня github.com без обращения к сети и записи

### Requirement: Проверка доступности
До регистрации система MUST проверить репозиторий и доступную ревизию его default branch токеном экземпляра. При ошибке доступа, токена, ревизии, лимита или временном сбое система MUST NOT создавать или изменять проект. Проверка MUST NOT скачивать архив исходников.

#### Scenario: Доступный репозиторий
- **WHEN** токен имеет доступ к репозиторию и основной ревизии
- **THEN** регистрация использует полученные GitHub ID, полное имя и канонический URL

#### Scenario: Недоступный или пустой репозиторий
- **WHEN** репозиторий не найден, недоступен либо не имеет доступной основной ревизии
- **THEN** регистрация отклоняется с объяснением, состояние проектов не меняется

### Requirement: Сохранение регистрации
Успешная регистрация MUST сохранять устойчивый локальный ID проекта, стабильный GitHub ID, имя `owner/repo` и канонический URL. Бот MUST подтверждать результат только после фиксации записи, показывать имя, URL и локальный ID и пояснять, что анализ не запущен. Проект MUST сохраняться после перезапуска.

#### Scenario: Новый проект
- **WHEN** проверенный репозиторий ещё не зарегистрирован
- **THEN** создаётся активный проект и бот отвечает «Репозиторий добавлен» с его данными и пояснением об отсутствии запуска анализа

### Requirement: Идемпотентность и восстановление
Повторные и конкурентные добавления одного GitHub ID MUST приводить к одной записи и одному локальному ID. Варианты регистра, `.git` и `/` MUST NOT создавать дубликаты. При повторе бот MUST сообщать «Репозиторий уже отслеживается». Удалённая запись MUST восстанавливаться с прежним ID и историей и ответом «Отслеживание восстановлено».

#### Scenario: Одновременное добавление
- **WHEN** два разрешённых запроса добавляют один GitHub-репозиторий
- **THEN** оба получают один локальный ID, в БД остаётся один проект

#### Scenario: Новое имя того же репозитория
- **WHEN** GitHub возвращает прежний GitHub ID с новым каноническим именем
- **THEN** обновляются имя и URL существующего проекта без смены локального ID и потери истории

#### Scenario: Восстановление
- **WHEN** GitHub ID принадлежит удалённой записи
- **THEN** эта запись становится активной, сохраняя локальный ID, зависимости и историю

### Requirement: Существующие записи без GitHub ID
Система MUST сохранять ранее созданные проекты и их историю. При единственном совпадении нормализованного URL с записью без GitHub ID регистрация MUST привязать GitHub ID к ней. При нескольких совпадениях либо противоречии сохранённых идентичностей операция MUST завершиться объяснимой ошибкой без автоматического объединения и изменения записей.

#### Scenario: Привязка старой записи
- **WHEN** единственный прежний проект без GitHub ID имеет соответствующий URL
- **THEN** используется его локальный ID и сохраняется история

#### Scenario: Неоднозначные старые данные
- **WHEN** найдены несколько прежних записей с соответствующим URL либо конфликт GitHub ID и URL
- **THEN** бот сообщает о конфликте существующих записей и необходимости исправления администратором, не меняя данные

### Requirement: Независимость от анализа
Регистрация MUST NOT запускать мониторинг, создавать результаты или менять инвентарь зависимостей. Новый проект MUST быть виден в `/status` и `/attention` как проект без проверок и оценок. Сохранённая история восстановленного проекта MUST сохранять прежнюю семантику чтения и актуальности снимков.

#### Scenario: Просмотр нового проекта
- **WHEN** после добавления нового репозитория вызываются `/status` и `/attention`
- **THEN** проект показан без успешного снимка и без выдуманных оценок; число его текущих зависимостей равно нулю

### Requirement: Ошибки и текстовая доставка
Бот MUST различать безопасные причины отказа GitHub и ошибку хранения. При лимите MUST показывать известное время повторения без автоматического бесконечного повтора. При ошибке хранения MUST отвечать «Не удалось добавить репозиторий. Попробуйте позже». SQL, тела ответов, токены и трассировки MUST NOT попадать в ответ. Ответ MUST передаваться обычным текстом; сбой отправки MUST NOT откатывать уже сохранённый проект.

#### Scenario: Ошибка записи
- **WHEN** запись в БД не удаётся
- **THEN** изменения откатываются, успех не сообщается, пользователь получает нейтральный ответ, техническая причина сохраняется в журнале без секретов

#### Scenario: Сообщение не доставлено после сохранения
- **WHEN** Telegram отклоняет подтверждение после фиксации проекта
- **THEN** регистрация остаётся в БД, повтор команды возвращает существующий локальный ID
