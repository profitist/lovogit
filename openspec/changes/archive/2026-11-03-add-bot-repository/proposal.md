# Proposal

## Why

`/add_repo` сейчас является заглушкой: GitHub-провайдер получает исходники, но пользователь не может зарегистрировать репозиторий в общем списке проектов. Нужна регистрация через бота, чтобы будущий исполнитель мониторинга получал устойчивый список проектов из БД.

## What Changes

- Реализовать `/add_repo <github-url>` для участников разрешённых чатов; проверять доступ до сети и БД.
- Проверять URL и доступность основной ревизии существующим GitHub-провайдером, сохранять имя `owner/repo`, канонический URL и стабильный GitHub ID, возвращать локальный ID проекта.
- Повторное и одновременное добавление одного GitHub-репозитория не создаёт дубликатов; удалённая запись восстанавливается с прежним локальным ID и историей.
- После регистрации проект виден в `/status` и `/attention` без фиктивных оценок. Регистрация не скачивает архив, не извлекает зависимости и не запускает анализ.
- Уточнить документацию и `/help`: проекты теперь добавляются через бота; токены и разрешённые чаты остаются настройками экземпляра. Это явно заменяет прежнее решение в `docs/dev-docs.md`, `docs/frontend.md` и `docs/backlog.md` об отложенном подключении через бота.

## Capabilities

### New Capabilities

- `bot-repository-registration`: проверенное и идемпотентное добавление GitHub-репозитория в общий список проектов через защищённую команду бота.

### Modified Capabilities

- `bot-project-status`: подсказка при отсутствии проектов указывает `/add_repo`, а не настройку при развёртывании.
- `bot-project-attention`: такая же подсказка при отсутствии проектов. Остальное поведение обеих команд сохраняется.

## Impact

Сервис регистрации в `src/lovogit/app/services/`, отдельный роутер команды и его подключение в `src/lovogit/bot/`, модель `Repo` и новая Alembic-миграция стабильной GitHub-идентичности, тесты и документация. Используются существующие `GitHubProvider.resolve`, URL-парсер и настройки `GitHubSettings`; новые зависимости не требуются. Исключены агент, планировщик, `/check`, удаление и переименование через команды, конфигурационный импорт проектов, Mini App API и роли администратора. Как и для остальных защищённых команд, все участники разрешённого чата имеют равные права; регистрация относится ко всему экземпляру.
