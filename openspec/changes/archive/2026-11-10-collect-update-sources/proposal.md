# Proposal

## Why

Compare пока ожидает готовое описание изменения библиотеки, но источники для него никто не собирает. Реализованный PyPI-провайдер позволяет первым небольшим шагом получить материалы двух конкретных релизов, сохранив происхождение данных и явно обозначив отсутствие changelog.

## What Changes

- Добавить независимый асинхронный сервис сбора материалов по имени пакета, текущей и целевой версиям через существующий `PyPiProvider`.
- Возвращать метаданные обеих версий, исходные описания с content type, опубликованные ссылки с классификацией по назначению и происхождением.
- Выделять изменения `requires_python` и состава строк `requires_dist` как различия метаданных, сохраняя признак `dynamic` и сведения об отзыве целевого релиза.
- Отличать отсутствие явно обозначенных ссылок на изменения от ошибок получения релизов; не подменять эти случаи выводом об отсутствии изменений.
- Ограничить этот change сбором данных в памяти. Загрузка страниц, анализ текста моделью, поиск по коду, генерация тестов, очередь, запись в БД и изменение графа comparer не входят в него.

## Capabilities

### New Capabilities

- `update-source-collection`: сбор метаданных и опубликованных источников для заданной пары версий Python-пакета через PyPI, без оценки совместимости.

### Modified Capabilities

Нет. Контракты GitHub-снимков и состояния мониторинга не меняются.

## Impact

- Новые сервис и DTO рядом с существующим сервисным слоем `src/lovogit/app/services/`.
- Используется существующий публичный контракт `app/providers/pypi.py` и `pypi_dto.py`; новые зависимости, настройки, сетевые клиенты и миграции не требуются.
- Добавляются тесты сервиса и документация его вызова. Telegram-бот, песочница, провайдер GitHub и незавершённый LangGraph не затрагиваются.
