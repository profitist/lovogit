# Spec Delta

## Purpose

Извлекать из уже загруженных материалов утверждения об изменениях библиотеки для заданного обновления, сохраняя проверяемые подтверждения и ограничения применимости и покрытия.

## ADDED Requirements

### Requirement: Анализ готовых материалов
Система MUST принимать загруженные источники с парой версий и анализировать только успешно полученные непустые тексты. Происхождение и ошибки загрузки MUST сохраняться. При отсутствии материалов система MUST возвращать явный результат без вызова модели, без поиска новых источников, чтения кода проекта или записи состояния.

#### Scenario: Источники недоступны
- **WHEN** все ссылки пропущены или завершились ошибкой загрузки
- **THEN** результат сообщает отсутствие материалов, сохраняет причины и не вызывает модель

### Requirement: Интервал обновления
Система MUST учитывать изменения всех обнаруженных промежуточных релизов в интервале `(current, target]`. Версии MUST сравниваться по правилам Python-версий, а не лексикографически. Изменения с неизвестной версией MUST передаваться отдельно как неподтверждённые для интервала. Некорректные, равные или обратные границы MUST отклоняться до вызова модели.

#### Scenario: Промежуточные релизы
- **WHEN** обновление идёт с 1.0 до 1.3, а источник содержит изменения 1.0, 1.1, 1.2, 1.3 и 2.0
- **THEN** в подтверждённый по версии список попадают только 1.1, 1.2 и 1.3

#### Scenario: Версия не установлена
- **WHEN** источник описывает изменение без определимой версии
- **THEN** утверждение с подтверждением сохраняется отдельно с неизвестной применимостью

### Requirement: Категории изменений
Система MUST извлекать изменения API, поведения, настроек, значений по умолчанию и требований к Python/зависимостям. Каждая запись MUST иметь категорию, описание, версию либо явную неопределённость и необязательный символ. Отсутствующий в источнике символ MUST NOT выдумываться или быть обязательным для сохранения изменения.

#### Scenario: Изменено значение по умолчанию
- **WHEN** релиз описывает новое значение настройки без названия функции
- **THEN** запись сохраняется в соответствующей категории без обязательного символа API

### Requirement: Проверяемые подтверждения
Каждое принятое утверждение MUST содержать хотя бы один непустой точный фрагмент из фактически переданного модели текста и ссылку на известный источник. Система MUST проверять схему, источники и цитаты программно. Не прошедшие проверку записи MUST исключаться с явной причиной. Наличие цитаты MUST NOT объявляться доказательством правильности интерпретации.

#### Scenario: Выдуманный источник или цитата
- **WHEN** модель возвращает неизвестный идентификатор источника или отсутствующую в нём цитату
- **THEN** запись отклоняется с причиной, остальные валидные записи сохраняются

### Requirement: Ограничения покрытия
Результат MUST отдельно сообщать обработанные и необработанные материалы, найденные версии, отказы проверки и неопределённость покрытия интервала. Пустой список изменений MUST NOT означать отсутствие изменений или совместимость. Успешная обработка всех переданных текстов MUST NOT означать полноту истории релизов.

#### Scenario: Неполная история
- **WHEN** доступны материалы только 1.3 для обновления 1.0 → 1.3
- **THEN** найденные изменения сохраняются, но покрытие промежуточных релизов не объявляется полным

### Requirement: Ограниченное выполнение
Система MUST ограничивать число и размер материалов, объём ответа, число вызовов модели и время выполнения. Исключённые по лимитам материалы MUST явно отражаться в результате. Документы MUST передаваться как недоверенные данные без инструментов, выполнения инструкций или автоматического обхода ссылок.

#### Scenario: Инструкции внутри changelog
- **WHEN** текст требует прочитать файл, перейти по ссылке или изменить поведение агента
- **THEN** анализ не предоставляет такой возможности и обрабатывает текст только как материал

### Requirement: Ошибки анализа и отмена
Ошибка модели, timeout, отказ или невалидный ответ MUST отличаться от отсутствия материалов и успешного пустого результата. Ошибка одного документа MUST NOT скрывать готовые результаты других документов. Внешняя отмена MUST передаваться вызывающему. Система MUST NOT присваивать оценку совместимости.

#### Scenario: Частичный сбой модели
- **WHEN** один документ успешно обработан, а следующий завершился timeout или невалидным ответом
- **THEN** результат сохраняет готовые изменения и явно указывает ошибку второго документа

#### Scenario: Отмена анализа
- **WHEN** вызывающий отменяет выполнение
- **THEN** отмена передаётся без преобразования и новые вызовы модели не начинаются
