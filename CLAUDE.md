# SessionFlow

Локальная Kanban-доска для управления сессиями Claude Code: приложение само находит сессии, отслеживает их состояние и показывает на одной доске.

Статус: проектирование, версия 0.1. Кода пока нет.

## Документация

- [docs/mvp.md](docs/mvp.md) — зачем проект, для кого, что входит в MVP и когда он готов.
- [docs/dev-docs.md](docs/dev-docs.md) — сущности, доска, мониторинг, состояния, AI-анализ, архитектура, безопасность.
- [docs/backlog.md](docs/backlog.md) — что отложено на версии 0.2–1.0.
- [docs/frontend.md](docs/frontend.md) — дизайн фронтенда: экраны, структура кода, контракт API и событий.

Перед работой над задачей сверяйся с `docs/mvp.md`: если задача не входит в MVP, её место в `docs/backlog.md`.

## Стек

- Backend: Python, FastAPI, SQLite, Pydantic, Watchdog.
- Frontend: React, TypeScript, drag-and-drop, обновление без перезагрузки.
- AI: LangChain, LangGraph (позже), LLM API или локальная модель.
- Интеграции: Claude Code, Git, MCP (позже).

## Правила, которые нельзя нарушать

1. **Порядок разработки:** сначала надёжный мониторинг и полезная доска, потом понимание контекста через ИИ, и только потом автономное управление. Доска должна работать, даже когда ИИ недоступен.
2. **Статус сессии и статус задачи хранятся раздельно.** Перемещение карточки пользователем не меняет фактическое состояние процесса.
3. **Неопределённость показывается как неопределённость.** Если состояние нельзя установить достоверно — статус «неизвестно», а не догадка. Долгое бездействие само по себе не значит «зависла».
4. **Состояние определяется по событиям и процессам**, а не только по тексту диалога. ИИ не помечает задачу завершённой из-за сообщения об успехе в истории.
5. **Всё локально.** История сессий не уходит наружу без явной настройки; в облачную LLM — только нужное для анализа, секреты вырезаются.
6. **Только чтение.** SessionFlow не меняет файлы проектов и не выполняет команды в терминале без явного действия пользователя.
7. **Мониторинг не падает целиком** из-за одной битой записи: ошибка фиксируется, остальные сессии обрабатываются дальше. События не обрабатываются повторно, после перезапуска состояние восстанавливается.
8. **MCP — внешний интерфейс**, а не обязательный транспорт между компонентами приложения.
